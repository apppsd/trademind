# ISSUE-20261013-07 交易日历缺少覆盖范围与越界保护

## 2026-10-14 独立复核：重新开放

[Task14-01](../tasks/TASK-20261014-01-独立校验改进任务完成质量.md)发现原关闭证据不覆盖以下问题，status恢复open，resolved日期撤回；下方原解决记录保留为历史，当前关闭条件以本节及原Task验收共同判断。

日历更新只做并集，不能删除错误交易日；覆盖首尾之间的数据空档被误认定为已确认休市。

### 最小复现与代码证据
临时CSV旧日期为2026-10-12/13/14，新的合成输入仅列12/14。实际merge_official_calendar更新后13仍为交易日（True），因calendar_update.py:56使用set(existing)|set(incoming)。这不是对真实交易所日期的判断，仅证明更新无法纠正错误行。

继续输入2030-01-02/03，实际TradingCalendar.covers(2028-06-01)=True且is_trading_day=False；此前未提供2027～2029任何有效覆盖证据。calendar.py:35-36只以最早/最晚交易日推断连续覆盖，合并器也没有确认覆盖区间。原要求区分空档未知与已确认休市仍未满足。现有测试只验证并集合入、去重、首尾越界，未覆盖撤销日期/覆盖中间空档。

本轮全部为合成离线输入，不认定任何示例日实际开市或休市，不读取或更新生产日历。

### 剩余关闭条件
- [x] 定义输入的有效覆盖区间，对该区间按权威完整集合替换/校正，保留区间外历史；不能让并集永久保留已更正的交易日。（段级替换：与官方输入区间重叠的已确认段整段撤回、区间外段保留历史；复核反例13不再为交易日）
- [x] 用明确已确认区间表达覆盖，拒绝推断中间未提供年份为休市；来源与覆盖元数据必须一致，首尾节假日也需有覆盖依据。（已确认段+>14天未确认空档模型；meta记录csv_sha256由load()比对）
- [x] 补日期撤销、跨年缺段、重叠来源/更新失败原子性及覆盖不足零收费启动反例，再验收原Task。（撤销/跨年缺段/meta写失败可检测/hash不一致反例新增；覆盖不足零收费首轮已验保留）

## 问题表现
自动模式默认加载仅含2026年的fixture日历，缺来源/有效覆盖范围元数据。覆盖外日期与已确认休市同为False；next在无未来日期时回退最后日期，add_trading_days可能IndexError。

证据级别：隔离复现的日期越界缺陷及未来运行缺口。本轮仅分析，尚未实施修复。

## 影响
年度切换或资料缺失时可能静默等待、给出过去的未来日期或抛底层异常。不能将本轮2027示例认定为真实交易日，也未判定2026节假日清单正确与否。

## 环境
2026-10-13，Windows / Python 3.12.10，main / F:\Project\TradeMind，宿主当前未提交源码。其他Agent正在修改相关文件，实施前须再次核对。隔离实验只用Mock/Future/临时SQLite/fixture，不读取.env、不联网、不调用模型、不操作生产账户或容器。

## 复现方式
TradingCalendar.load()末日2026-12-31。查询覆盖外2027-01-04：is_trading_day=False；next返回2026-12-31；add_trading_days(该日,1)抛IndexError。仅加载本地CSV，不联网。

### 代码定位
- src/trademind/market/calendar.py:27/45/57：默认fixture、next回退、add_trading_days直接索引。
- data/fixtures/calendar_xshg.csv最后一行为2026-12-31。
- scripts/generate_fixtures.py：简化HOLIDAYS与固定2026生成范围，不是长期官方日历更新流程。
- src/trademind/execution/auto_paper.py:main调用TradingCalendar.load，session_seconds按该日历安排启动。
- docs/project/operations.md已人工注明覆盖至2026-12-31及下一年更新；本Issue针对程序不能区分覆盖不足/休市和导航越界，不重复人工提醒。

## 原因分析
只有交易日列表，没有可证明的非交易日覆盖范围；越界与休市没有区分，导航方法用边界日期代替未知。

## 最终解决方法
2026-10-14 由 [TASK-20261013-15](../tasks/TASK-20261013-15-完善交易日历覆盖与更新门禁.md) 实施修复（设计见[ARCH-018](../architecture/18-calendar-ownership.md)）。
**（2026-10-14复核后更正：下文第3条"并集合并"已被段级替换语义取代——与本节"问题表现"同轮复核确认并集不能删除错误日期。现行语义：官方输入按其区间完整陈述，重叠已确认段整段撤回、区间外段保留历史，覆盖建模为已确认段+未确认空档，meta新增csv_sha256供load()一致性比对。原文其余条目仍有效。）**
- `TradingCalendar`带显式`coverage_start/coverage_end`；成员/导航一律`_require_covered`，覆盖外抛`CalendarCoverageError`（含覆盖范围与所查日期）——原"覆盖外=False""next回退末日""add_trading_days IndexError"三条缺陷路径全部消除；范围内非交易日才是休市事实，导航永不截断边界。
- `coverage_warnings()`：覆盖尾≤20个交易日提示更新；缺`.meta.json`出处提示未验证。
- 更新接口（纯离线）：运营者下载官方CSV→`scripts/update_calendar.py`→`market/calendar_update.py::merge_official_calendar`并集合并、严格解析、默认拒绝缩小覆盖（`--allow-shrink`显式确认）、原子替换并写`.meta.json`旁证（source/version/checked_at/范围）；程序永不编造交易日、永不联网。
- `auto_paper.py`每tick覆盖检查：覆盖外/临近结尾→健康"日历覆盖不足"、停止模拟与付费请求等待人工。
