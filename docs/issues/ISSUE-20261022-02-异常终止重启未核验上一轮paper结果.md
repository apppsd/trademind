# ISSUE-20261022-02 异常终止重启未核验上一轮paper结果

## 问题表现与影响
Task22-03二轮正常shutdown分类已独立通过，Issue22-01 resolved结论保留。但外部硬终止可能不执行finally，不能据此保证未知结果跨重启暂停。

Supervisor构造只读取旧halted，忽略旧phase/terminal/report_path及排空报告。旧paper未完成、halted=false且报告缺失时，重启在交易时段直接新启paper，可能进入收费预检/交易循环；writer锁释放不证明上次账户/模型结果已收敛。暂无生产资金异常证据。

## 环境与复现
2026-10-22 Windows / D:\trademind，Task22-03二轮源码。临时目录写旧状态phase=paper、terminal=false、halted=false、旧heartbeat、report_path指向缺失文件；Mock日历返回交易时段，launch只记录命令并返回Mock child。重建Supervisor并tick，输出halted=false、new_paper=true。没有真实进程启动/强杀、网络或生产库操作。可执行片段见[Task22-04](../tasks/TASK-20261022-04-独立复验本地停止修复.md)二轮复审节。

## 原因分析
正常shutdown保护依赖收尾代码实际执行。硬终止可跳过收尾，启动恢复却直接信任旧halted=false，没有把未完成旧轮分类为待核对。

## 最终解决方法与关闭条件
未修复，归Task22-01启动/恢复范围，由原Owner明确文件所有权后实施，不回退Task22-03已通过的正常停止修复。

## 2026-10-22修复（Task22-01原Owner，待独立复验）

`Supervisor.__init__` 新增 `_recover_interrupted_paper` 启动恢复分类：旧状态 `phase=paper` 且无 terminal 标记（硬终止跳过收尾）时——①旧 `child_pid` 仍存活 → 置 halted（子进程结果未知）；②按 `result_policy` 分类旧 `report_path`（缺失/损坏/failed/model_pending/worker_active → 置 halted 并原子持久化，原因注明"上一轮模拟进程被外部终止"）；③报告合法完成 → 不暂停正常恢复；④serve 阶段被杀、首次启动、干净停止（terminal=true）均不误暂停；⑤已有 halted 不被清除。tick 状态新增 `child_pid` 供核验。对照回归 6 项（缺失报告halt、合法报告恢复、干净停止、serve被杀、存活子进程、既有halt保留）全绿；复验者风格反例（损坏报告+phase=paper+terminal=false）输出 halted=True/new_paper=False。`run_local.py` 未改动。真实实例已用修复版重启（graceful stop→start，pid 267928）。

关闭条件逐项：①启动前核验旧进程/未终态报告 ✓（child_pid探活+report分类；锁核验由既有writer lease承担）；②已有halt不清除、合法完成可恢复、首启/干净停止/serve恢复不误暂停 ✓（对照回归）；③隔离覆盖 ✓；④operations/current-status已同步精确恢复语义 ✓。

- 启动前核验上一轮进程/锁、未终态paper报告及账户证据；缺失/损坏/未知结果持久halt，不自动新启paper。
- 已有halt不可自动清除；合法完成可恢复，首次实验/干净停止/正常serve休市恢复不误暂停。
- 隔离覆盖旧worker仍活跃、缺失/损坏/未知/合法报告及已有halt；不用生产强杀或收费造单验证。
- operations/current-status同步撤回“任意被杀直接start即可安全恢复”保证，明确人工核对步骤。
