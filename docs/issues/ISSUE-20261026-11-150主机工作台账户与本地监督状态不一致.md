# ISSUE-20261026-11 150主机工作台账户与本地监督状态不一致

## 问题表现与证据

2026-10-26 对 150 主机只读核对，仓库 `D:\trademind` 在 `76cacaa`，Git 工作区干净；未启动或停止服务。

- 127.0.0.1:8321 有监听，`/workbench/` 返回 200。`/api/workbench/overview`、`runtime`、`account/series` 均返回 200，但信封的账户别名是默认 `paper-001`，不是既定千元实验账户 `paper-t0-local-1k`；概要和运行响应为 `partial`。
- 该运行接口报告自动监督状态与观察服务状态文件不存在，不能以页面 200 推断千元实验正在运行。
- 千元实验运行目录中 `auto-paper-state.json` 的最后心跳为 `2026-10-23T08:37:45.411778+00:00`，记录的监督 PID 232988、子进程 PID 10672 当前均不在进程列表；8321 的监听 PID 为另一个进程。状态文件中的 `halted=false` 是旧快照，不能当当前健康结论。

这是运行实例与目标账户的可复现落差。没有证据表明发生错误下单或账本损失。

## 影响

用户看到的 V2 页面可能是可访问但账户不对、监督信息缺失的旧实例。若据此宣称千元实验或 V2 运行验收通过，会误判实际状态。代码返修的工程测试不等于现有进程已加载新版本。

## 根因状态（2026-10-26 Task26-18 只读核对后定位）

两个独立事实叠加：

1. **8321 是默认配置的 serve 实例**：PID 741336 服务 76cacaa 的 V2 静态包（`index-OWTujUSF.js`），但 `/api/status` 身份为账户 `paper-001`、根库、`t0.enabled=false`、`jev_provider=stub`、V1 股票池——即旧默认配置进程，从未绑定千元实验账户。启动命令/时间未能获取（主机无 wmic/pwsh），启动来源保持未验证。
2. **千元实验监督链在 10-23 被外部硬终止**：最后会话 10-23 14:21–14:57 报告排空安全（`valid_result_not_executed`、worker 排空、0 挂单、日报已生成），进入 serve 等待开市后最后心跳 10-23 16:37:45 +08；此后无日志（log 无 10-24 及以后记录）、无 stop 标志，PID 232988/10672/495924 均不存在。非程序自停、非风控锁定；主机是否重启未验证。按 ARCH-026 恢复语义属合法完成分类，人工 start 可正常恢复。

核对记录：writer 锁文件残留但持有进程已死（内核自动释放），当前无第二 writer；账户最后 0 持仓/0 挂单。切换/回退方案见 [TASK-20261026-18](../tasks/TASK-20261026-18-核对150主机运行实例并准备安全切换.md)，实际启停待用户授权。
