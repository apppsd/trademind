# ISSUE-20261014-02 东财ETF分钟成交量未统一份额单位

## 问题表现
AKShareAdapter.get_minute_bars将成交量原值直接写入统一份额volume。官方ETF1m示例的413、420929元、10.192元不能按413份解释；量额均价相差约100倍。

## 影响
东财作为新浪备用时会带来成交量口径差异，影响VWAP、量比、跨源对比以及量额门禁；连接成功不等于可直接切换。

## 环境与复现方式
2026-10-14 main Windows，现有.venv+pandas。向实际AKShareAdapter注入假SDK/DataFrame，使用[AKShare官方ETF1m示例](https://akshare.akfamily.xyz/data/fund/fund_public.html)511220的成交量/金额/价格，合成OHLC边界。输出volume=413，amount/volume=1019.198547，price_range=10.19～10.193，unit_check_ok=False。未调用真实API；详见[研究](../research/20261014-free-minute-sources.md)。

## 原因分析
[live.py](../../src/trademind/market/adapters/live.py)直接Decimal(r[成交量])，而[base.py](../../src/trademind/market/base.py)约定MinuteBar.volume为shares/units。当前没有ETF分钟源级单位转换及量额关系检查；quality.py的分钟归一化只检查部分价格边界，不检查该差异。

## 尝试过的方法
隔离复现证明示例映射问题；没有将所有接口统一乘100，也未以模拟行声明三只ETF盘中已通过。
2026-10-14 工程修复（[Task14-03](../tasks/TASK-20261014-03-核验免费ETF备用源与单位映射.md)）：ETF 1m 分支接口级 `_ETF_MINUTE_LOT=100` 换算 + 行级量额关系自检（违例整源拒绝，不静默错单位）+ 显式不复权；12 项离线回归通过。三ETF真实取样因东财对本机出口 IP 的临时软封禁未完成（6 轮有界尝试，错误类别与时点见[研究报告](../research/20261014-etf-minute-unit-verification.md)），未伪造样本。

## 最终解决方法
[Task14-03](../tasks/TASK-20261014-03-核验免费ETF备用源与单位映射.md)已实施：仅 `fund_etf_hist_min_em` 分支按接口级常量换算手→份额（官方 511220 样本证据 `420929/(413×100)=10.1920`），股票分支原样透传；每行校验 `成交额/份额 ∈ [low×0.98, high×1.02]`，零成交⇒零额；单位/结构违例整源 DataUnavailable。若上游改变口径，自检必然破坏并显式拒绝，不会错误数据进入订单链。

## 剩余风险
文档示例能证明当前映射不可靠，不能证明所有ETF/周期的源单位永远相同。与新浪已有单位检查统一语义，禁止重复转换。
