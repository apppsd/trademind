# ISSUE-20261016-02 短暂买入条件被全账户评估冷却跳过

## 问题表现与影响
用户希望验证模拟买卖链，实际订单/成交一直0。进一步只读复查发现：513050.SH的11:18条件BUY计划在11:21及11:27部分观测中已满足全部入场条件且未命中失效条件，但对应持久化意图仍为global model evaluation cooldown，未进入JEV判断。

这是现有低频设计的已观察取舍，**不是实现违反已冻结300秒契约的证据**；它使“全天条件都没满足”的归因不成立，提示当前评估节奏可能覆盖不到短暂触发窗口。不能据此断言JEV必定BUY、Guard必定通过或有可盈利交易。

## 环境与事实
- 2026-10-16上海约17:00～17:05；trademind-auto-1 healthy，phase=serve、halted=false；订单/成交0。
- 配置仅513050.SH、513100.SH、518880.SH三ETF，fast_eval_seconds=300、strategy_refresh_seconds=900、strategy_ttl_seconds=1200。预算/模型门槛未修改。
- 今日13份策略按证券分布8/2/3；意图中非全局冷却30条（无可行动条件29、JEV不确定1），只有1次JEV动作请求，并非1008条WAIT都做过模型判断。

## 原因分析
[fast_pipeline.py](../../src/trademind/agents/fast_pipeline.py)先以fast-eval:<account>检查全账户300秒冷却，再获取/复用计划、build_fast_state与JEV；因此已有计划的本地条件满足，也不会在冷却中直接升级为JEV评估。[runner.py](../../src/trademind/runner.py)轮转候选且单worker异步工作，实际覆盖仍有明显差异，不能仅由轮转存在推断三ETF模型评估均匀。

[冻结需求](../requirements-jev-fast-decision.md)第TASK-02节明确300秒最短间隔及全池最多一个模型候选；本轮不将它当实现bug、不绕费用门禁或直接缩短配置。需要保存档案覆盖分析和设计评审，比较低频预算与短时信号覆盖的取舍。
