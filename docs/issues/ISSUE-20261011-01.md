# 提示晋级真实门禁与回滚验证未落地

## 问题表现与影响
1. evaluation/prompt_eval.py的evaluate_promotion_eligibility在real_archive_bundle=None时跳过真实留出检查，使用测试dummy报告会返回PROMOTE；需求规定缺真实证据不能晋级。传入非空collected只检查状态/contexts数量，没有证明时间切分及候选响应/版本关联。
2. 晋级读取contract_failure_rate/forbidden_recommendation_rate，但evaluate实际输出contract_failures/dangerous_suggestions；完整pass报告也因缺指标被REJECT。现有晋级单测自己构造另一套指标，未覆盖真实报告接口。
3. verify_version_rollback只查询attempt键，按版本字符串不同返回cache_invalidated，并硬编码ledger/orders_untouched=True；不选择版本、不切换planner或实际验证缓存/持仓/费用。StrategyPlanner仍导入固定STRATEGY_PROMPT/STRATEGY_PROMPT_VERSION；注册表存在不等于运行版本可选。

这些函数当前检索仅定义与测试使用，没有自动放行订单的运行接线；本Issue不是已观察到的实盘订单事故。原11-08已保持in_progress，但其“工程全部完成”声明过强。

## 环境与复现
2026-10-11，Windows宿主现有venv，不读取.env/联网。
复用tests/test_prompt_promotion.py的_make_dummy_report，baseline strategy-2/candidate strategy-3调用晋级函数且不传真实档案：PROMOTE。
复用tests/test_prompt_eval.py的dataset/bundle生成实际evaluate报告后调用晋级：REJECT。实际指标名与所读取指标名不同。
源码检查prompt_eval.py回滚函数及strategy_planner.py版本导入，未发现切换操作；现有回滚测试使用DummyRepo，仅检查返回声明。

## 根因
新增晋级/回滚辅助函数未与生产报告Schema和运行版本选择接口形成闭环；测试输入模拟了期望接口，未使用真实评测产物和持久化账户前后快照。真实证据门禁被设为可选参数。

## 解决与关闭条件
原Task08负责：统一报告Schema并使用实际evaluate产物集成测试；真实晋级缺档/时间切分/版本证据不足必须INCOMPLETE；区分工程通过和真实晋级。明确运行版本选择/缓存绑定，实际切换隔离paper版本并比较账本/订单/预算/冷却前后快照，不能以常量声明替代验证。不得为过测试放宽真实门禁。
