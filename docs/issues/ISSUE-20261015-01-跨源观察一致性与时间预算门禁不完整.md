# ISSUE-20261015-01 跨源观察一致性与时间预算门禁不完整

## 2026-10-15 修复后独立复验：缓存分支仍可绕过，重新open

[复验Task15-02](../tasks/TASK-20261015-02-复验跨源观察四项修复.md)独立全量570 passed、相关八套件103 passed，确认首次观察、整轮预算、观察接受策略及无缓存时的持续拒绝/一致解除均已修复；保留下方实施记录。但原关闭条件要求再次请求不能洗掉拒绝，缓存命中分支尚未检查`_divergence`。

实际同一pref、递增as_of的隔离反例（无网络）：
1. 两源1.500先一致观察；900秒稀疏间隔将到期时，主源仍1.500、备用已1.600，先查询最近1小时窗口，因观察未到期而缓存合格主源窗口。
2. 11秒后查询同证券最近2天窗口（同pref），因查询范围更宽无法复用窄缓存，触发观察并发现6.67%差异；本轮quality.ok=False、`_divergence`存在。
3. 再过1秒查询最近1小时窗口，仍命中12秒前缓存：quality.ok=True、limit_violations=[]、两源调用次数不变，而`_divergence`仍存在。没有合格一致观察解除拒绝。

输出：warm_ok=true、wide_query_ok=false、divergence_still_present=true、narrow_cached_ok=true、cached_violations=[]、calls_before=calls_after=[3,3]；三时点as_of为2026-10-08 09:54:50/09:55:01/09:55:02+08:00。另以不同pref缓存也独立复现，不依赖固定as_of或关闭观察。

根因：router.py:339～356缓存命中直接返回；持续拒绝仅在427～442的重新取数路径写入report.limit_violations。发现差异时也未清理该证券其他已有缓存。pipeline.reference_price和builder依赖该字段拒绝质量问题，不能以内部字典仍存在就宣称所有返回已拒绝。当前主链通常查询2天窗口，本轮未证明实际订单受影响；本例证明公开路由支持的窗口/缓存路径不满足持续拒绝验收。

修复仍归Task14-04，不另建重复Issue。缓存命中也须遵守当前证券拒绝状态；覆盖同pref窄→宽→窄、不同pref或周期已有缓存、再次请求及一次合格一致观察后的恢复。可以无效化争议证券缓存或统一经过拒绝检查，但不能仅改测试窗口或取消缓存。

**2026-10-15晚已修复**：缓存命中统一经过拒绝检查——`get_minute_bars` 缓存命中条件加入 `instrument_id not in self._divergence`，拒绝存在期间任何键（任意pref/周期）的缓存都不返回，统一落入重新取数路径由拒绝状态写入violations；合格一致观察解除状态后缓存路径自然恢复。同pref窄→宽→窄回归 `test_cross_check_standing_refusal_not_bypassed_via_cache`（修复前复现本节反例：calls不变、cached_violations=[]；修复后第3步重新取数并观察）。

下方已修四项及570项通过记录为真实实施证据；本次重开仅针对第1项关闭条件在缓存路径的剩余缺口。没有修改业务源码或测试。

## 问题表现
Task14-04的基础质量回退已修复原四反例，但启用cross_check后还有四项工程缺口：

1. 已发现两源差异超限，仍可改选其中备用源并返回quality.ok=True、缓存该结果；下游只看limit_violations时不会据此拒绝新风险。
2. 观察请求的等待不计入剩余整轮预算，实际整轮可超过round_timeout_seconds。
3. 首次观察以last_mono=0为基准，单调时钟值小于配置间隔时静默跳过，既有测试在当前环境失败。
4. 观察源未复用as_of可见性/闭合/质量接受策略，未来才可见的数据也参与价格差异计算。

## 影响
可选交叉观察的防护和时延声明未满足验收。默认cross_check_enabled=False，本轮未切换运行配置，没有证据证明当前生产或实际订单受影响；基础新浪/东财质量回退仍可保留。不能把单条字符串source_rejections当成已阻止交易的证据。

## 原因分析
[router.py](../../src/trademind/market/router.py)：
- 113/218行last_mono零值与绝对单调时钟比较，未区分从未观察与观察间隔未到。
- 205～250行_maybe_cross_check独立取per_source_timeout，不接收整轮deadline/as_of/接受策略；241行normalize结果的_rep未检查。
- 358行交叉差异把当前候选加入拒绝后继续pref；下一个候选因全局last_mono刚更新而跳过比较，随后379行无limit_violations直接选定并缓存。
- 既有差异测试强制interval=0，第二候选也被重新比较，恰好掩盖正常900秒间隔下的绕过。

## 最终解决方法
2026-10-15由原Task14-04实施修复（工程口径），实施与验证记录见该Task"2026-10-15修复"一节。修复语义：
- **差异成为持续拒绝状态**：观察超容差后，router按instrument记录拒绝状态（`_divergence`），后续pref候选与再次请求一律把该差异note写入`report.limit_violations`并拒绝、不缓存，直到一次合格且一致的观察将其解除；不再立即改选争议源洗掉。
- **观察共用整轮预算**：`_maybe_cross_check`接收整轮deadline，观察等待钳至剩余预算；预算已耗尽时不发起请求、不消耗观察计数（status=skipped）；超时弃置的worker只写本地box，不污染路由状态。
- **首次观察显式建模**：`last_mono=None`表示从未观察，首次必观察；router时钟改为可注入`_clock`，测试用可控时钟覆盖初始、后续与北京日切换。
- **观察沿用候选接受策略**：观察源按同一as_of可见性过滤、同一normalize质量检查（`_rep`已检查）与同一新鲜度上限判定；不合格观察记为status=unqualified，不比较、不算一致、不解除既有拒绝。
- 附加设计修正：差异拒绝不再对单源记退避（责任在源对之间不明确，持续拒绝由instrument级状态承担，请求消耗由每日限额约束）——避免修复缺口1时引入退避倍增与跨标的源沉默。
