# ISSUE-20261007-09 安装依赖指向无应用代码的旧提交

## 问题表现与影响

git cat-file -e 6d848108b2d853c26ad376d6929d58f9b4a74c6c:pyproject.toml 返回128。

首版验收阻塞，不能因为现有93项测试通过视为功能完成。

## 环境与复现

Windows、项目 .venv Python、SQLite、fixture/stub。动态场景运行 .venv/Scripts/python.exe docs/research/20261007-audit-repro.py；静态证据见 [验收报告](../research/20261007-code-audit.md)。

## 原因分析

pip freeze保存editable远程依赖，固定旧文档提交无pyproject.toml，README先执行requirements会尝试安装它。

## 代码范围

requirements.txt、pyproject.toml、打包资源、安装文档。

## 尝试过的方法

独立验收核对与临时库复现，没有修改应用代码。

## 最终解决方法

移除指向旧文档提交的自依赖，改为本地 -e .，不升级或更换依赖工具。wheel 包含 SQLite Schema、网页和 fixture 数据；安装后从 sys.prefix/share/trademind 读取离线数据。新临时 venv 实际安装 requirements、测试、构建/安装 wheel，并在仓库外运行离线 CLI。

实施记录：[TASK-20261007-35](../tasks/TASK-20261007-35-修复验收.md)。

## 验证结果与剩余风险

本缺陷已通过强断言回归；全套 133 passed，原失败证据与最终命令见 [复验报告](../research/20261007-code-audit.md#修复复验2026-10-07)。真实供应商能力与前瞻观察仍未验证，不与本缺陷关闭混为一谈。
