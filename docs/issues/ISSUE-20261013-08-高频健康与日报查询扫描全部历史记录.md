# ISSUE-20261013-08 高频健康与日报查询扫描全部历史记录

## 问题表现
read_intraday_health每次读取全部model_calls和该账户全部策略history；auto每5秒调用。日报read_snapshot读取全部账户的model_calls/context_snapshots/intents，再用Python过滤。历史增长会持续放大读量。

证据级别：已确认无界查询；真实性能影响未测。本轮仅分析，尚未实施修复。

## 影响
长时间自动观察后可能增加内存、SQLite读负载和健康心跳延迟；本轮不宣称发生超时。历史账本重建确需期初信息，不能简单截断所有历史造成资金/盈亏错误。

## 环境
2026-10-13，Windows / Python 3.12.10，main / F:\Project\TradeMind，宿主当前未提交源码。其他Agent正在修改相关文件，实施前须再次核对。隔离实验只用Mock/Future/临时SQLite/fixture，不读取.env、不联网、不调用模型、不操作生产账户或容器。

## 复现方式
临时SQLite插入一条created_at=2020-01-01的合成model_calls记录，read_snapshot(path,'isolated')仍返回该行。查询本身没有日期过滤；健康函数源码确认fetchall。未做规模压测，预计复杂度为O(历史行数)，实际延迟必须测量。

### 代码定位
- src/trademind/execution/paper_run.py:207/219：history fetchall、model_calls全表fetchall。
- src/trademind/execution/auto_paper.py:142/184：tick读取健康，循环sleep(5)。
- src/trademind/reports/daily.py:47-66：read_snapshot无日参数，calls/contexts/intents全表读取。
- src/trademind/api/app.py:daily_report_lifespan按分钟生成今日/昨日报告；schema.sql现有索引未保证这些全表查询有界。
- 本轮确认PaperRun.record_progress只写最后决策的有界摘要，未发现每次重写全部results；不将其列为O(N²)问题。

## 原因分析
日期/账户关联与聚合主要在Python内完成；高频路径复用了全历史扫描，缺少可度量的查询量上界。

## 尝试过的方法
已做文档与对应源码/现有测试对照、以上隔离核查；没有修改实现或运行状态。实验过程和整体去重见[TASK-20261013-11](../tasks/TASK-20261013-11-代码对照改进规划.md)。

## 最终解决方法
2026-10-14 由 [TASK-20261013-16](../tasks/TASK-20261013-16-限制健康与日报历史查询范围.md) 实施修复：
- `read_intraday_health`：model_calls 与 strategy_plan_history 查询加上海日 ±2 天 UTC ISO 窗口谓词（精确上海日过滤保留在 Python）， intents 当日最近意图回退改为窗口内有界候选 + Python 精确挑选；索引复用迁移2 的 ix_calls_created / ix_plan_hist_acct_avail / ix_intents_created。
- 日报 `read_snapshot` 增加可选 `window=(start, stop)`：calls/intents ±2 天、contexts 7 天回看、plans ±2 天，全部走索引；account_events 有意保持全量（期初账本必须按全部事件重放，属“可验证的必要历史”，不视为本缺陷）。`window=None` 保留旧无界路径兼容。
- 唯一可见语义差异：持仓无当期可用行情时 `price_time` 展示字段只在快照 7 天内解析，更旧显示 null；所有金额/口径字段不变。

## 验证结果
已验证（2026-10-14，Windows / Python 3.12，隔离 tmp SQLite，无网络）：
- 合成 1/30/365 天历史 + 多账户 + 跨日未结预留：今日日报与“仅当日数据”基线全量相等（参数化测试）；健康读取中昨日失败计入 SQL 边际但被精确日过滤排除、当日失败仍计数。
- EXPLAIN QUERY PLAN：四个窗口查询分别命中 ix_calls_created / ix_ctx_asof / ix_intents_created / ix_plan_hist_acct_avail，无全表 SCAN；窗口行数有界由测试固定。
- 规模实测（32,407 行合成库）：read_snapshot 22.8ms/32,407 行 → 0.8ms/242 行；generate_report 2.3ms；read_intraday_health 0.9ms/次。
- 全量回归 481 passed（`python -m pytest tests --ignore=tests/test_multi_asset.py --color=no`；该文件因环境缺 pandas 一直排除）。
未验证：真实运行/容器内生效与真实长期运行库上的实际负载变化；峰值内存未单独测量（以查询行数有界 + 耗时实测为证）。

## 剩余风险
修复后风险收敛为：新增查询路径若绕过窗口（新报表/新健康字段）需沿用同一窗口模式；真实长期运行库上的收益需五交易日观察确认。不得为通过验证放宽行情/资金/预算门禁，真实闭环仍由原验收任务判断。
