# 未来日线修订提前挤掉历史可见版本

## 表现与影响
同一日线存在早可见revision1和晚可见revision2时，DatasetRouter.get_daily_bars先全局normalize选最高revision，ContextBuilder之后才过滤available_at。尚不可见的revision2被过滤后，该日已可见的revision1已丢失，历史Context会退用前一交易日价格，未来修订的存在改变早期输入。不是未来价格直接进入Context；是历史行缺失与时点稳定性错误。

旧默认日线Context路径可达，ContextBuilder对其他持仓日线估值也采用该顺序；实际影响取决于源是否返回这种多版本记录，暂无生产证据。当前快速链分钟路由支持as_of先过滤，合成对照通过；不将日线缺口推断为分钟路径故障。

## 离线复现与实际数据流
Windows/.venv Python3.12，禁止socket/凭据文件，纯内存合成adapter注入实际DatasetRouter实例，再用实际ContextBuilder和合成TradingCalendar（覆盖足够90日窗口），无模型/订单/数据库写入。

样本：10-09 close99；10-12 revision1 close100、available_at=10-12 15:30+08；同日revision2 close110、available_at=10-13 16:00+08。所有Bar为合法带时区模型，source_time=对应日15:00、provider相同。

1. adapter仅返回前两行，build(as_of=10-12 16:00+08) close=100。

4. normalize_minute_bars对同分钟revision1已可见/revision2晚2分钟可见、as_of中间时刻，正确保留revision1。

## 根因与区别
quality.normalize_bars的最高版本归并不带as_of；router.get_daily_bars无时点参数且先归并。features.bars_visible_at晚于归并，无法找回旧版本；裸列表过滤又未选择每日期最新可见版本，不能简单跳过质量归并来修复。分钟normalize/as_of顺序已有实现，不应回退其门禁。旧Issue07-07是行情撮合、Thesis来源和Replay隔离；19-01是结果标签到期/终点取值，均不同根因，保持原状态。
