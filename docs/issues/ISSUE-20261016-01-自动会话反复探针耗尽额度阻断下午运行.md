# ISSUE-20261016-01 自动会话反复探针耗尽额度阻断下午运行

## 问题表现
2026-10-16 14:20:52～14:56:45连续8次自动paper启动被`probe_pair_unavailable:ProviderError`阻断，报告data=[]、新增model_calls=0。当天总请求used=24/100未用完，但probe=10/10，新的双探针需再预约2次，因此无法进入行情/策略循环。

## 影响
下午余下连续交易时间无法评估新机会；仅看总模型预算未耗尽或容器healthy无法发现该细分额度阻塞。它解释14:20后的无交易机会评估，不解释之前已经发生的策略观望，也不证明若恢复循环就会产生买卖。

## 环境
新镜像ab2f739f01ab，1000元paper，sina_etf，auto每次有界paper均携带--probe-models。2026-10-16 16:25左右只读核查；真实订单/成交均0，halted=false。

## 复现与证据
- 真实审计：flash_probe5次成功；jev_probe3次成功/2次失败；探针共10次；strategy13次成功；jev动作1次成功。合计24次，与预算probe10/strategy13/jev1/used24一致。
- 09:50、09:55两轮JEV探针失败，各消耗一对探针；09:58、11:03、13:20三轮成功paper启动分别再次探针，累计耗完10次。
- 自动单轮最长3600秒，下午13:20:30进入paper，14:20:31结束，再启动14:20:52开始被探针预算拒绝；之后每约5分钟重复被拒，无额外收费请求。
- 16:25只读SQLite budget day=2026-10-16、used24、probe10、strategy13、jev1；配置daily_decision_call_budget100、probe_request_limit10。完整报告文件、查询和计数见[Task16-01](../tasks/TASK-20261016-01-核查近期没有买卖记录的原因.md)。没有重新发探针或清预算。

## 原因分析
- [auto_paper.py](../../src/trademind/execution/auto_paper.py)的session_seconds每次最多3600秒；start(paper)总传--probe-models，因此午休/轮时限/重试都会创建新进程并再次探针。
- [runner.py](../../src/trademind/runner.py)的_fast_paper_preflight先执行_check_fast_probe_budget，失败直接返回，不进入取数/模型；报告只保留异常类型，无法从通用ProviderError直接区分探针次数、总请求或费用预留阻塞。
- [daily_budget.py](../../src/trademind/models/daily_budget.py)的check_probe_pair检查probe+2>probe_request_limit，10+2>10必然命中。该拒绝本身正确，问题在会话生命周期、探针安排与每日细分预算缺少协同及可解释状态。
- 不同于已resolved的Issue12-02请求数/审计行口径差异，本日24请求与24行/24次attempts一致；不得重开原计数Issue。
