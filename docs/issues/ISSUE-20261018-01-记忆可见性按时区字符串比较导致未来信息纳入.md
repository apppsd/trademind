# 记忆可见性按时区字符串比较导致未来信息纳入

## 表现与影响
合成混合时区记忆经MemoryStore.visible查询，会把真实晚7小时的记录返回，也会遗漏真实早1小时的记录。同一as_of瞬间分别表示为UTC和北京时间，返回集合不同，违反既有available_at时点隔离契约。Pipeline旧默认链将此查询作为ContextBuilder.memory_view，builder直接采用返回memory_id，未再比较available_at。快速链未证实使用该记忆入口；目前无真实记忆/历史决策受影响证据，不推断生产交易损失。

## 环境与可复现证据
Windows/.venv Python3.12、临时SQLite、纯合成MemoryRecord，socket连接和真实凭据文件读取均禁止。调用Repository.save_memory后MemoryStore.visible，与MemoryRecord.visible_at比较：

| 记录available_at | 查询as_of | datetime契约 | 实际仓储 |
|---|---|---|---|
| 2026-10-12T09:00:00+00:00 | 2026-10-12T10:00:00+08:00（02:00Z） | 不可见（晚7小时） | 返回 |
| 2026-10-12T09:00:00+08:00（01:00Z） | 2026-10-12T02:00:00+00:00 | 可见（早1小时） | 遗漏 |

两行查询as_of为同一瞬间，结果却不同。最小复现（仅内存库，无网络/配置）：

```python
from datetime import datetime as DT
from trademind.storage import Database, Repository
from trademind.memory import MemoryStore
from trademind.domain.memory import MemoryRecord
with_db = Database('sqlite:///:memory:')
try:
    repo = Repository(with_db)
    available = DT.fromisoformat('2026-10-12T09:00:00+00:00')
    cutoff = DT.fromisoformat('2026-10-12T10:00:00+08:00')
    record = MemoryRecord(id='synthetic', trace_id='synthetic', created_at=available,
        memory_id='future', type='EVENT', instrument_id='513050.SH',
        available_at=available, summary='synthetic')
    repo.save_memory(record)
    assert record.visible_at(cutoff) is False
    assert MemoryStore(repo).visible(cutoff, '513050.SH')  # 缺陷：非空
finally:
    with_db.close()
```

## 原因与范围
src/trademind/storage/db.py::save_memory保留datetime.isoformat偏移，memories_visible以TEXT `available_at <= as_of.isoformat()`比较；ISO字符串字典序不等于跨时区瞬间顺序。domain/memory.py接受任意带时区datetime且visible_at本身正确，仓储没有统一比较。不是旧Issue07-07的行情/Thesis来源时间或Replay真实provider隔离根因，旧Issue保持resolved。

## 验证及限制
同区等时点、retracted排除、valid_until过期排除控制通过；storage/contracts/context共51项现有测试通过仍未覆盖混合时区。首轮50通过/1项因隔离器拒读.env而未运行，通过将config.ENV_FILE_PATH指向临时不存在的合成路径后51项全部通过；未读真实.env，不将隔离拒绝当产品失败。四份审查源码在成功套件前后哈希稳定。未改业务/生产，无模型/行情或交易。
