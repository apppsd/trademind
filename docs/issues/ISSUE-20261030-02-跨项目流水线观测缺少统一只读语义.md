# ISSUE-20261030-02 跨项目流水线观测缺少统一只读语义

## 已观察事实与证据

本地打开`frontend/src/router.ts`、`src/trademind/api/workbench_routes.py`、`read_models.py`、`observer_app.py`及trader的`apps/trader/web.py`、`quant/dashboard/service.py`。已有运行/活动/账户查询，但分属两个服务；没有核实到覆盖两项目的统一node/edge/event接口与日志摘要接口。TradeMind runtime费用来自日报，不能自动视为实时余额；trader run-ledger与TradeMind paper-runs也不是相同事件口径。

这是已观察到的**接入语义缺口/未知问题**，不是认定交易系统故障；酷炫页面新功能由Task负责。完整路径、读写分类和来源见[研究页](../research/RESEARCH-20261030-cool-dataflow-frontend.md)。

## 风险与根因边界

现有展示用途不同，账户身份、源时间/采样时间、健康与就绪、费用预留/结算口径需要映射。直接拼接会把web可读当交易健康、把旧快照画成实时事件或把示意线当因果；这些是接入风险，未声称在当前UI复现。旧app.py部分GET依赖Pipeline，不可只按HTTP方法认定零业务副作用。根因限于已读契约分散；150现场与性能未检查。

## 处置与关闭标准

2026-10-30用户经Trade Ops决定：一个统一运维驾驶舱 Unified Ops Cockpit，单壳左trader / 右TradeMind同时展示，共享管线/粒子视觉，不做两个独立网站。详细决策/承载取舍见研究页决策段；默认扩展TradeMind Vue工作台，未实现。

由04冻结双系统映射、来源和pane ownership，05验证同一split壳的样例表现，06后续将两系统只读适配接入同一壳并验收；trader345/346只提供映射与左窗Owner交接。必须可展示missing/stale/error/unknown、项目/主机/账户/时间/证据；未知字段不补0，缺因果不画因果。只读白名单覆盖写方法拒绝、无provider/交易副作用与有界查询。日志源无法接入时明确禁用即可，不能用模拟假实时关闭问题。必须验证单侧断连不拖垮另一侧，双源实际验收前保持open。
