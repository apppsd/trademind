# ISSUE-20261013-09 数据库升级只登记固定版本且不拒绝未来版本

### 最小复现与代码证据
隔离raw SQLite创建schema_migrations=99的DELETE模式库，计算文件SHA256，调用实际Database并收到SchemaVersionError后再次计算，database_hash_unchanged=False。db.py:69先PRAGMA journal_mode=WAL，97行之后才在migrate检查版本。原test_future_schema_version_refused_untouched先用Database创建已是WAL的库，只对表名/行数做比较，不能证明拒绝路径字节不变。

隔离真实Ledger.deposit记录500，随后仅在临时测试库把account_state.cash及payload cash/equity改为999。实际backup_to生成副本，verify_database副本返回ok=True，事件仍为500。verify_database只检查integrity/外键/版本/引用闭包，没有重放资金、持仓或校验冻结/活动预留。原“恢复副本完成账本/订单/预留一致性”的验收尚未满足；不是断言生产库损坏。

515项回归通过，说明已有测试未覆盖DELETE未来库和财务不一致备份；生产库未打开/迁移，干净wheel安装及Linux侧仍未验证。

### 剩余关闭条件
- [x] 在任何持久PRAGMA、DDL、恢复操作前检查未知未来版本；补DELETE/WAL未来库文件hash及结构/数据不变验证，保证失败连接正确释放。（`_refuse_newer_schema`以`mode=ro&immutable=1`在任何连接/PRAGMA之前预检；DELETE-journal与WAL未来库字节不变、无-wal/-shm、失败连接关闭）
- [x] 增加只读事件重放与账户余额/持仓/版本及冻结活动预留对账；若仅是物理完整性检查，不得用ok宣称账本恢复可用。（`_replay_account_ledger`五项对账入verify_database，ledger_ok并入ok）
- [x] 补篡改余额/持仓/活动预留、缺事件/孤立成交及合格副本的正反例，按原要求补离线安装/资源验证；全部仅用临时库。（现金/持仓/活动预留/缺事件/合格副本正反例齐备；孤立成交由引用闭包覆盖；离线安装保留未验项）

## 问题表现
Database.migrate每次执行整份IF NOT EXISTS schema.sql，只登记version=1。没有顺序升级、结构变更校验、未来版本拒绝或可验证备份恢复入口；已经新增strategy_plan_history但Schema版本仍为1。

证据级别：隔离复现的版本保护缺口；当前库升级损坏未观察。本轮仅分析，尚未实施修复。

## 影响
后续列/索引/约束变动或旧程序打开新库时，无法依赖当前版本号判断兼容。当前追加表幂等工作并不因此被否定；本轮没有验证生产数据库损坏。

## 环境
2026-10-13，Windows / Python 3.12.10，main / F:\Project\TradeMind，宿主当前未提交源码。其他Agent正在修改相关文件，实施前须再次核对。隔离实验只用Mock/Future/临时SQLite/fixture，不读取.env、不联网、不调用模型、不操作生产账户或容器。

## 复现方式
临时库Database初始化后插入合成schema_migrations版本99，再用实际Database打开同一路径：仍成功，applied_migrations=[1,99]。未改生产库。既有IF NOT EXISTS不会自动修改已存在列/约束，可由后续旧Schema集成测试确认。

- src/trademind/storage/schema.sql：schema_migrations及后续strategy_plan_history等表共同存在。

- docs/project/setup.md无覆盖数据库结构升级、SQLite WAL一致备份及恢复验证的完整流程。

## 原因分析
最初单文件bootstrap机制被当成长期版本迁移，登记号未表达实际结构演进；没有旧程序拒绝未知新版本的门禁。

## 最终解决方法
2026-10-14 由 [TASK-20261013-17](../tasks/TASK-20261013-17-建立可验证数据库升级与恢复流程.md) 实施修复（设计见[ARCH-019](../architecture/19-db-upgrade-backup.md)）：
- `schema_migrations`注册表最先建立且最先读取；已应用版本高于`LATEST_SCHEMA_VERSION`立即抛`SchemaVersionError`拒绝打开/修改——发生在任何结构写入之前，原"插入版本99仍能打开"路径被关闭。
- v1基线schema.sql幂等执行后登记版本1；新增`MIGRATIONS`有序升级表，每版本一个`BEGIN IMMEDIATE`事务，失败整体回滚（含版本戳）下次打开重试；全部附加性变更。
- 迁移2：`intents.created_at`列+payload回填+四个报表窗口索引（TASK-20261013-16窗口化读取的前置）。
- `backup_to(target)`：SQLite backup API在线一致备份（含WAL）、拒绝覆盖；`verify_database(path)`：原始只读连接校验integrity/外键/schema版本/orders-fills-events-reservations引用闭包；恢复流程=副本→verify→打开（operations.md已记录）。
