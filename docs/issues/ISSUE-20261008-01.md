# ISSUE-20261008-01 T0风险退出与交易计数未接入运行流程

## 问题表现

止损/尾盘退出辅助函数未被主流程调用；成交不更新连续亏损计数，日切不重置买入计数。

## 影响

当前双模型最小模拟盘不能通过启动验收；已有模块单测不代表运行门禁生效。

## 环境

Windows，本地 .venv，main / F:\Project\TradeMind，2026-10-08；离线检查，无真实凭据读取或收费API调用。

## 复现方式

rg 在 src 中查 check_stop_loss_exit、check_session_close_exit、record_trade_result、reset_daily_counters，仅发现定义。模型WAIT路径直接返回，未检查已有持仓退出。

代码位置：src/trademind/guard/guard.py:54、61、284；pipeline.py:307。

## 原因分析

组件实现后没有装配进入成交、日切和持仓评估生命周期；计数仅内存存储。

## 尝试过的方法

只读检查、离线全套测试及必要隔离复现，证据统一见[检查报告](../research/20261008-t0-code-review.md)。

## 最终解决方法

Pipeline在模型前评估确定性止损/尾盘清仓，并经Guard/OMS；Guard从成交事件重建完整平仓亏损连续次数，审批计数事务内持久化并按交易日恢复。 实施记录见TASK-20261008-02。

## 验证结果

179项现有测试通过，但没有覆盖本问题的完整运行行为。关闭要求：已有持仓在模型WAIT/审核失败时仍可由代码触发0.8%止损、14:55退出并经Guard/OMS；成交后正确更新亏损数，跨交易日/重启恢复计数；新仓JEV门禁保留。

## 剩余风险

离线修复不替代预算内真实双模型/分钟行情能力验证。
