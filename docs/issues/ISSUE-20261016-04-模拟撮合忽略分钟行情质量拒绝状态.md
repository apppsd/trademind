# ISSUE-20261016-04 模拟撮合忽略分钟行情质量拒绝状态

## 2026-10-17在途独立核查
[Task17-02](../tasks/TASK-20261017-02-复查在途账本撮合与数量修复.md)用实际router双源1.500/1.600重跑：report.ok=false、持续拒绝存在时，PaperBroker已不生成Fill，原反例通过。Task16-07仍in_progress/Claude Code，完整接受策略、诊断/兼容及文档关闭条件继续由原Owner收口，本Issue保持open。

## 问题表现与实际证据
使用实际DatasetRouter、两FakeSource在同一10:01分钟分别给close1.500/1.600，启用交叉观察。实际router返回rows=1、QualityReport.ok=false、limit_violations=1、证券持续拒绝存在；随后实际PaperBroker(minute_only=True).try_fill对10:00提交的100份限价1.500买单仍生成price1.500的Fill，持续拒绝仍存在。全程合成行情，无网络或生产写入。

## 原因与代码位置
paper.py:44以bars,_丢弃QualityReport；_eligible_minute_bars未传as_of/新鲜度接受策略，仅检查时间。router在全部源不合格时有意返回最不坏窗口与拒绝报告，供下游拒绝；ContextBuilder检查limit_violations，但PaperBroker没有。OMS._poll_fill检查数量、时序、限价，不能补回已经丢失的质量来源。

## 影响与边界
已有挂单可能在跨源差异或OHLC质量失败的窗口上产生模拟成交，污染账本和策略评估。这是撮合消费者缺口，不是Issue15-01缓存修复再次失败；生产无订单，尚无真实坏成交证据。

## 复现方法
1. 复用tests/test_minute_source_routing.py的FakeSource、bar、router_with、policy，创建10:01的1.500/1.600双源，cross_check_enabled=True。
2. 实际router请求10:00～10:01:03，确认report.ok=false和_divergence存在。
3. 向同router连接的PaperBroker提交合成10:00订单，quantity100、limit1.500、minute_only=True，try_fill于10:01:03返回Fill；修复后应无成交并有可解释拒绝。
