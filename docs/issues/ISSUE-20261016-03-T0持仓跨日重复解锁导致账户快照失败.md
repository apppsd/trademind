# ISSUE-20261016-03 T0持仓跨日重复解锁导致账户快照失败

## 2026-10-17在途独立核查
[Task17-02](../tasks/TASK-20261017-02-复查在途账本撮合与数量修复.md)对变化后的代码隔离复查：100份T0当日买入→次日日切后quantity/available均100，事件重放后仍100/100、bought_today=0，原异常未再现。Task16-06仍由Claude Code实施且未声明完成，Issue保持open，不能以该单例替代全部回归/文档/真实验收。

## 问题表现与实际证据
临时数据库：2026-10-12买入513050.SH 100份，当日quantity=available=100；调用on_new_trading_day(2026-10-13)抛出ValidationError：available_quantity cannot exceed quantity，事务回滚。rebuild_from_events后内部quantity=100、available=100、bought_today=100，再次跨日同样失败。另一个由持久化快照新建的Ledger会从quantity-available重算bought_today，行为与同进程/事件重放不一致。

## 原因与代码位置
ledger.py:289将T+0买入计入bought_today，293又立即增加available；335次日无区别再次增加available。事件重放159/163/175重复相同逻辑，而_load用quantity-available重算未解锁量。PositionState禁止available>quantity，故跨日产生异常而非悄悄接受错误数量。

## 影响与边界
T0有未平仓余额跨日时，同进程或事件重放恢复后的账户日切可能持续失败，影响估值、风险退出与报表；生产当前无持仓，未观察到真实触发，不能把它当此前零成交原因。

## 复现方法
1. 用临时SQLite和get_profile('513050.SH').fees创建Ledger，存入1000；合成10月12日10:00的100份BUY Fill并apply_fill，确认当日quantity/available均100。
2. 同一Ledger调用10月13日on_new_trading_day，记录上述校验异常及事务回滚；随后rebuild_from_events再调用，同样失败。
3. 对照从同一临时库新建Ledger的_load路径，比较三条恢复路径的结算计数。
