# ISSUE-20261008-03 最小模拟盘CLI错误成功与运行配置不一致

## 问题表现

t0-paper在决策报错时仍返回success/exit0；steps重复相同时点；serve重新加载配置，未继承CLI的500账户改动。

## 影响

当前双模型最小模拟盘不能通过启动验收；已有模块单测不代表运行门禁生效。

## 环境

Windows，本地 .venv，main / F:\Project\TradeMind，2026-10-08；离线检查，无真实凭据读取或收费API调用。

## 复现方式

临时SQLite/无凭据AppConfig，patch run_decision返回INJECTED_DECISION_FAILURE；steps=2仍exit0、status success，两条decision.error存在。只读核对load_config和now的位置可确认配置/时间差异。

代码位置：src/trademind/runner.py:127、143、156；runner.py:86。

## 原因分析

命令无总体错误汇总与启动验收状态；T0配置只在命令内临时改写；循环时间未前进。

## 尝试过的方法

只读检查、离线全套测试及必要隔离复现，证据统一见[检查报告](../research/20261008-t0-code-review.md)。

## 最终解决方法

CLI统一--config，T0要求显式paper/白名单配置；循环等待实际间隔并用当前时间轮询，聚合错误返回非0，provider未验证明确返回unverified/2。 实施记录见TASK-20261008-02。

## 验证结果

179项现有测试通过，但没有覆盖本问题的完整运行行为。关闭要求：错误必须非0且报告安全WAIT/启动未通过/执行成功区别；runner/status/serve/recover共用确切配置与账户；steps和撮合时点向前推进，防止制造未来账户事件。

## 剩余风险

离线修复不替代预算内真实双模型/分钟行情能力验证。
