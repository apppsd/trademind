# 买入计划退出条件未关联SELL动作

## 问题与影响边界

本地真实计划档案共23份，8份含BUY；其中7份包含exit_conditions却未将SELL列入allowed_actions（5份BUY/HOLD/WAIT，2份BUY/WAIT）。这些计划可被当前生产校验器接受，但即使持仓已可卖且退出条件命中，build_fast_state也不会向JEV开放SELL。

实际本地账户无订单、无成交、无持仓，尚无真实延迟退出或损失证据。程序time_stop/stop_loss/session_close仍独立经Guard/OMS工作；不是所有退出失效。该问题也不是Issue13-04的AND/OR解释不一致：此处退出条件已经命中，缺的是动作资格。

## 环境与复现

Python3.12.15，main，独立SQLite目录`data/runtime/audit-20261025-exit-probe`；复用`tests/test_fast_decision.py::make_pipe`，Flash complete与JEV session.post均为Mock，不读真实Key、不联网。

1. 包装make_pipe的Flash返回：保留原策略全部条件（entry close>1，exit close<2），仅将allowed_actions设为BUY/HOLD/WAIT、holding_horizon_seconds设为1200，以避免五分钟时触发时间退出。
2. 10:00执行run_decision得到BUY/order_created=True；时钟+1分钟poll_fills返回1笔，持有100份。
3. 再+4分钟run_decision，读取Mock JEV最后请求state：持仓100，`conditions_allow(SELL, plan, features)=True`，offered_actions却为WAIT/HOLD/BUY，无SELL，最终返回WAIT。生产模拟账户未改动。

## 原因分析

- `domain/strategy.py::StrategyPlan.temporal`要求BUY具备入场条件，没有要求其退出方案能实际执行。
- `agents/strategy_planner.py::StrategyPlanner.get`仅校验“允许SELL时必须有exit_conditions”，没有校验反向关系。提示词要求不能替代程序验证。
- `context/fast_state.py::build_fast_state`同时要求持仓可卖、SELL在计划允许集合、退出条件命中，缺SELL就拒绝开放。

不应简单绕过allowed_actions强制卖出；应先明确可开仓计划必须具备的退出契约，或明确只靠程序风险退出的合法计划类型，再同步提示、校验、缓存和回归。
