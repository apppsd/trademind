# 自动状态未反映策略持续失败

## 问题表现与证据
2026-10-13 13:49及14:17：auto状态持续phase=paper、halted=false、中文“盘中模拟监控运行中”，Docker healthy；实际六次继而11次策略请求为空。auto_paper.tick只在paper子进程退出后读取最终报告；活跃子进程阶段仅看poll/deadline，没有盘中策略成功率/最近有效计划/当前失败原因反馈。因此“健康/运行中”不能区分有效策略与持续失败。单轮最长3600秒，结束前无该层策略状态提示；费用截至14:17估值0.208697442368元。既有planner冷却与provider breaker存在，不能说无任何退避。

## 影响
用户可能误判模型正常决策；同类失败仍按现有冷却发起策略请求，监督层无法根据持续失败降级重试或提示。没有订单本身不是缺陷；必须区分市场观望、执行不可达与模型失败。默认Docker健康检查继续只表示监督进程活着。

## 原因与边界
监督层现有职责只管理子进程/时段/最终报告，不读取盘中策略健康；这是当前代码可证实的缺口，不是“模型拒绝”的根因。模型空输出归Issue13-01，计费请求/审计差异归Issue12-02。

## 修复与验收方向
由Task05增加只读盘中健康摘要、中文运行提示和有界失败退避；不扩大请求/费用限额，不把合法WAIT算模型失败，不启动第二writer。持续失败可停止新模型请求但不得中断已有持仓的确定性风险退出。真实降级与恢复由Task06核验，实施前保持open。

## 最终解决方法（2026-10-16，工程口径resolved）
[TASK-20261013-05](../tasks/TASK-20261013-05-盘中健康反馈与失败退避.md)核查收口（工程于10-13/14轮落地，原Owner未回写；同日随13-04授权改派收口）：
- **盘中健康摘要**：`paper_run.read_intraday_health` 只读产出六态中文状态（等待开市/行情不足/有效策略观望/策略请求失败退避/持仓风险处理/需要人工核对）+ 最近策略成功时间、连续失败数、失败原因（中文）、预算分项与count_semantics、持仓/订单数、下一允许请求时间；经 supervisor 状态文件、`/api/status`、页面与日报透出。Docker healthy 继续只表示进程存活——两层独立（2026-10-15晚实证：healthy容器同时报"需要人工核对"）。
- **有界失败退避**：账户级模型失败退避（首败300秒、连败翻倍、有效成功清零）；退避中拒绝新模型请求但不阻断已有持仓的确定性止损/期限退出/订单轮询；合法WAIT/冷却/资金不足不计模型失败。
- 钉住测试：`test_auto_paper.py::test_strategy_failure_backoff_recovery_and_account_day_isolation`、`::test_wait_cooldown_unaffordable_not_counted_as_failure_and_risk_exit_works_during_backoff`；套件31 passed，全量577 passed。
