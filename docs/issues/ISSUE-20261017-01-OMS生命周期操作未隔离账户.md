# OMS生命周期操作未隔离账户

## 问题与影响
同库多账户受单写者协议允许，但OMS部分生命周期操作没有核验订单account_id与绑定Ledger一致。隔离反例中A的OMS取消B订单后，B订单已CANCELLED、B的冻结160仍未释放；A的recover把B的SUBMITTING改UNKNOWN；A直接poll_fill(B订单)会扣A现金/向A加仓，而B订单变FILLED、B冻结不释放。正常Pipeline.poll_fills已按账户过滤，不能将直接OMS反例冒充正常轮询串账；但Pipeline.__init__的oms.recover是正常可达入口，会处理全库他人订单。

## 根因与代码
- src/trademind/execution/oms.py：_cancel/_poll_fill/_reconcile_unknown按全局order_id查询，无本账户检查；recover遍历全库open_orders；expire_approvals也未过滤账户。
- _submit虽校验本次intent账户，却对全库UNKNOWN/SUBMITTING/CANCEL_PENDING和同标的挂单作阻断，另账户可能误挡当前账户。
- src/trademind/storage/db.py：Repository.open_orders全库查询（本身可作管理查询，但账户服务必须显式约束）。Ledger.apply_fill未校验order.account_id匹配self.account_id，缺少防御边界。
- Pipeline._poll_fills/OMS.expire_stale_orders已过滤账户，不应回归破坏；ARCH-017的按库路径+账户租约不保护其他账户对象。
