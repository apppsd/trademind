# ISSUE-20261013-03 收盘未消费模型结果导致自动锁定

## 问题表现
2026-10-13上海16:55～16:59实际检查，trademind-auto-1 healthy/重启0，但自动状态phase=serve、halted=true，提示“仍有未消费的模型结果，暂停自动交易”。不是仅因收盘正常等待。

## 影响
自动交易处于保护性锁定；进程和页面健康不能视为继续交易可用。不得直接解除或用重启跳过资金/排空核验。本次无持仓、订单或成交，但不据此认定退出边界已正确处理。

## 环境与证据
Rancher Desktop / TradeMind auto服务，镜像f2a53f717d78…。容器内data/runtime/paper-runs/auto-5dbd6bab591d484b97ef57204a50d34b.json，上海14:20:50开始、14:57:00结束：status=incomplete、exit_code=2、model_pending=true；shutdown.unconsumed_result=true、worker_active=false、new_requests_closed=true，error=null。auto状态与报告一致，账户现金1000/持仓0/订单成交0。完整检查见Task08。

## 复现方式
只读auto-paper-state.json或/api/status，并读取上述报告的status/model_pending/shutdown；本次未重新启动循环复现。

## 原因分析

2026-10-13离线代码定位（TASK-20261013-10）确认直接根因：

1. `pipeline.py` 旧版 `close_model_worker` 把 `unconsumed_result` 定义为 `bool(_model_pending)`——只要退出时存在未消费future就为真，不区分该future已完成、已取消还是仍在运行。
2. 14:57收盘截止（`session_seconds`归零）时，最后一个策略future刚提交、尚未被同标的下一次轮询消费（单worker串行设计下约15秒后才轮到同标的），runner按deadline结束循环。
3. 排空时future被判定"未消费"→报告`model_pending=true`→监督器`result_policy`按既有保护策略`halted=true`。
4. `auto-paper-state.json`持久化halted且`Supervisor.__init__`重启时恢复该值，代码中无任何自动清除路径→跨日持续锁定。

即：即使future已正常完成（结果只是WAIT意图）、或从未启动（cancel成功、无任何模型调用），收盘也会锁死。保护策略本身（未知结果须人工核对）是正确的，缺陷在于把"已知终态的安全结果"也当成未知。

## 尝试过的方法

只读状态/API、容器报告与mode=ro账本核对。未重启、未解除锁定、未调用模型。

2026-10-13实施修复（TASK-20261013-10，仅改`pipeline.py`的`close_model_worker`及其分类辅助，不碰paper_run/auto_paper/监督器）：排空时对pending future做显式终态分类并写`control_audit`（action=model_drain）——`cancelled_before_start`（未启动无调用）、`model_error`（异常已按调用失败记录）、`expired_result_not_executed`（过期或账户版本已变，明确废弃）、`valid_result_not_executed`（仍有效但排空绝不执行；持仓由确定性风险退出覆盖、计划缓存下轮重评）、`no_pending_result`；仅`worker_still_active`（超时仍未结束）、不可分类结果（`unknown_result_shape`/`unknown_result_state`）及审计写入失败（`audit_write_failed`）保持`unconsumed_result=true`锁定。监督器保护策略与halted持久化不变；正常收盘不再误锁次日。隔离测试覆盖截止/未消费/worker活跃/超时/过期/账户版本变化正反例（tests/test_paper_run_report.py 12项通过）。

## 最终解决方法

代码根因已修复并有测试证据；遗留两件事保持本Issue open：

1. 容器内当前halted=true的存量锁定：须由TASK-20261013-06在部署新版镜像时，按授权、停机/排空确认及账户对账后处理；不得直接改halted=false或重启跳过。
2. 真实交易日收盘不再误锁、次日自动恢复：待下一个实际交易日观察验证后本Issue方可resolved。

## 验证结果与剩余风险

已验证：根因代码定位、修复实现、隔离测试（详见TASK-20261013-10验证节）。未验证：修复镜像未构建/部署（13-06范围）；真实盘中与跨日恢复未观察。剩余风险：若worker真超时仍活跃，锁定属预期保护，需人工核对而非缺陷。
