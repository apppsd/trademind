# ISSUE-20261014-01 分钟路由质量失败不尝试备用源

## 问题表现
DatasetRouter.get_minute_bars在首个支持分钟的源返回空列表、无效OHLC或陈旧数据时直接返回，不尝试后续合格源；首次归一化也没有as_of过滤。下游门禁拒绝后不回到路由重新取数。

## 影响
仅增加provider_pref不能形成有效的质量回退；有可用备用源时仍可能无上下文、NotFresh或DataUnavailable。没有证据证明未来行绕过下游订单门禁，不能以可用性修复放宽门禁。

## 环境与复现方式
2026-10-14 main Windows现有.venv，无网络。注入两Fake适配器，备用有合格行；主源分别空/无效/20分钟前/未来可见行，四种均选择primary，backup_calls=0。完整输入、结果与命令形式见[研究报告](../research/20261014-free-minute-sources.md)。

## 原因分析
[router.py](../../src/trademind/market/router.py)的get_minute_bars只在fetch异常或不支持分钟的空返回时continue；normalize_minute_bars未传end、不检查report.ok，也没有由调用者传入的freshness/闭合接受条件。缓存分支没有质量失败后重新选源语义。[builder.py](../../src/trademind/context/builder.py)事后检查无法触发回退。

## 尝试过的方法
只读源码与四组隔离反例；没有真实API重试或修复。

## 最终解决方法
[Task14-04](../tasks/TASK-20261014-04-实现分钟行情质量驱动多源回退.md)已实施（2026-10-14）：候选经可见性（仅 as_of 给定时）、归一化质量、非空、as_of+quote_max_age_seconds 新鲜度逐源判定，合格即选定；不合格记录原因并在轮时间预算内尝试下一源；全部不合格返回最不坏窗口交既有下游门禁拒绝；全部异常/无候选 RuntimeError。有界等待覆盖 akshare 15s 不可配超时。方案与实现一致，见[ARCH-020](../architecture/20-free-minute-source-routing.md)（含四条设计附录：空/陈旧不触发退避、无 as_of 不过滤取数路径、缓存重验穿透、预算钳制超时即止轮）。
