# 付费启动探针先于行情门禁且缺少双探针预算检查

## 问题表现与影响

阅读runner.cmd_t0_paper确认：原实现先_probe_fast_models，之后才预热行情、run_decision；闭市也会付费。单provider预算预留无法避免Flash花一次后JEV才发现配额不足。缺滚动指标只标DEGRADED，未禁止快速模型worker。

## 环境与复现

2026-10-09本地Python3.12/Rancher容器，jev_fast_decision；合成夜间/过期/缺分钟数据与隔离DB中仅剩一次配额，Mock HTTP记录零调用反例。无真实收费复现。

## 原因分析

配置/时段/数据/组合探针预算没有统一在付费请求之前；新快速链仅硬拒绝bars/freshness，其他必需窗口缺失仍可能申请策略。

## 修复与验证

Task18已实施免费预检先行、两探针只读预算检查、启动Flash单次、逐轮缺指标WAIT_DATA_QUALITY；保留程序风险退出优先。13新增反例及321完整回归通过，容器真实夜间显式带探针启动blocked、0新增调用/订单且工作台恢复通过。详见[验证报告](../research/20261009-task18-verification.md)。

## 关闭边界与剩余风险

本Issue只覆盖上述先收费/半探针/缺字段启动缺陷，容器零新增调用已验证，因此关闭本缺陷；不替代Task18全部运行收尾、Task16真实盘中质量或Task09交易闭环。预算检查以既有单writer为前提，违规并发writer不属于本次原子预留能力。
