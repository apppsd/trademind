当前提示见 [fast_prompts.py](../../src/trademind/agents/fast_prompts.py)，策略校验见 [strategy_planner.py](../../src/trademind/agents/strategy_planner.py)，证据见[提示契约验证](20261011-prompt-verification.md)。

已实现：九字段输出契约、实际校验器生成 Schema、有限特征/数值单位约束、时间与元数据由程序绑定、输入文本不作为指令、未知值不补零、WAIT 合法、有仓 SELL 与 BUY 准入分离、提示版本隔离缓存。当前 fast-2 的四题不适合改成普通聊天长报告。

仍值得补充：策略合法示例、真实模型响应的固定语义案例、失败分类与版本对比报告。既有离线测试能证明工程行为，不能代替真实供应商输出质量和交易验收。

## 建议实施顺序

1. **先补小型示例集。** 在策略提示补一组完整 WAIT 输入/输出，再补一组有仓退出、入场条件不成立的匹配示例。示例只展示格式和边界，不植入固定涨幅或催促交易。涉及 `fast_prompts.py` 和提示回归测试；变更须更新版本并核对缓存与容器镜像生效。
2. **建立固定评测案例。** 先做约 20～30 个工程案例，包含缺失必需数据、过期计划、可选 L1/NAV 缺失、不可卖仓位、成本不支持 BUY、亏损但应退出、恶意外部文本、非法字段/单位、重复执行。标注“允许动作集合”和“必须拒绝的动作”，没有证据时不强行标唯一交易方向。
3. **接入真实共同档案。** 按 Task17 采集、Task08 时间切分评测；保留输入时点、提示版本、模型版本、输出、费用及程序否决原因。调参集与后续留出集按时间隔离，未来成交/收益不回填进当时提示。离线档案检查无需新模型请求；重新评测模型输出须进入现有收费预算。
4. **最后考虑自动优化。** 有足够已标注档案后，评估 DSPy/GEPA 或 Promptfoo 适配、额外调用量与成本。限制优化次数，不让优化器修改硬风控、模型型号、资金、行情时点或预算门禁。

评测至少分别报告：格式/契约失败率、危险动作建议率、程序实际放行率、正确风险退出覆盖、无有效机会时的误交易、调用成功率、P50/P95 延迟、token 和费用。供应商错误也计入总请求分母；不能仅展示成功响应。行情缺失引发的安全 WAIT 与模型过度保守要分别统计。费用估算与账单费用区分，不把 JEV 评分解释成盈利概率。

格式错误反馈如需新增修复调用，应先核对现有有界修复逻辑和预算，仅反馈具体字段错误；不无限重试，不因“测试要成交”诱导 BUY。订单超时先核对状态与幂等标识，不能沿用生成文本的重试办法。

## 可复制的策略提示补充（建议稿，未接入）

追加到现有策略提示时保留原契约：

```text
以下示例只展示 JSON 格式和安全边界，不是当前行情，也不是推荐阈值。
实际决策必须使用本次提供的事实、output_schema 和 condition_contract。
缺少必需证据或不存在有效机会时，返回完整 WAIT 草案，不编造条件。
普通风险或反证不自动使整份计划失效；失效需给出支持的可计算条件。
入场不合适不意味着已有仓位不能退出；亏损不应阻止合理的减仓退出。
数量、订单权限、元数据和最终风控由程序处理。
```

WAIT 示例输入边界：无法形成有证据支持的可交易设置，且本次允许的持有期限上限至少为 300 秒。示例输出恰好九字段；300 只为格式演示，实际值须服从本次上限。

```json
{
  "trend": "现有证据不足以确认有效设置",
  "risk": "不新增敞口；无法确认潜在变动覆盖费用",
  "critic": "缺少支撑入场条件的必需证据",
  "reason": "等待可验证机会，不生成订单",
  "allowed_actions": ["WAIT"],
  "entry_conditions": [],
  "exit_conditions": [],
  "invalidation_conditions": [],
  "holding_horizon_seconds": 300
}
```

该示例用于 flash 计划草案；不能作为 JEV 四题请求的返回格式。有仓 SELL 示例实施时须用真实支持的字段、明确当前仓位及数值，先经过生产校验器，避免编造退出阈值。

## 给编程 Agent 的任务模板

项目 AGENTS 已包含任务认领、文档同步和完成门禁。下面作为每个具体任务的补充，不重复创建另一套规则：

```text
目标：修复/实现【具体行为】，触发场景是【输入与当前结果】。
先读 AGENTS、当前 Task 和关联代码，用可复现行为确认问题。
期望结果：【给出可检查的输出/状态变化】，非目标：【明确范围】。
只认领【文件/模块】，保留既有工作；不擅自换模型或放宽风控。
先记录失败证据；对必要行为增加针对性测试，再做最小修改。
核对异常、重启/重复调用和旧接口兼容；未验证项明确写原因。
回写 Task、受影响事实文档及验证结果，完成 Documentation Sync Check。
不读取或输出密钥；不擅自提交、推送、部署、调用收费 API 或实盘。
```

高级工程做法在本项目的具体形式：失败样本驱动修改、契约先于自由文本、少量明确职责、真实观测与持久化恢复、可回滚提示版本。每次只改一个可归因因素，用同一批输入比较，保留旧版本；不能仅凭“回答更专业”判断改进。
