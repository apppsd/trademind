# TradeMind 中文大屏工作台 V2 产品与交付要求

日期：2026-10-26；状态：**规划，未实现**。用户确认“深色科技驾驶舱、电脑大屏为主”；明确希望界面炫酷但简单、中文名称优先、能看标的具体曲线，并补充更多前端展示。执行入口：[Task26-02](tasks/TASK-20261026-02-规划中文大屏交易工作台重构.md)；架构：[ARCH-027](architecture/27-chinese-large-screen-workbench.md)。

本文是本批产品/视觉/接口语义的单一主文档。当前真实能力仍以`docs/project/current-status.md`为准，设计稿、Mock、截图不证明真实交易或盈利。

## 1. 目标与设计原则

1. 五秒内回答三件事：账户怎样、系统在做什么、当前关注标的怎样。五分钟内能解释“为什么没买/为什么卖/钱花到哪里”。
2. 首页少而准，详情按需展开；不把数据库表、trace_id和模型参数直接堆满首页。
3. 以中文名称识别标的，以曲线观察走势，以时间线理解过程；原始代码/ID保留在第二层以便核对。
4. 科技感来自深色层次、精确对齐、细线、克制光感、流畅响应；不靠持续闪烁、满屏粒子或“中奖式”盈利动画。
5. 模拟模式、行情时间/陈旧、未知费用、空仓/无成交等关键事实始终明确；不能为了好看隐藏限制。
6. 展示是观察，不是新交易策略。点击、刷新、切图表、打开页面都不能触发模型或订单。

## 3. 产品范围与优先级

### 首期必须具备

- 六个主页面：总览、行情、资产、策略、交易记录、日报；运行与设置从顶栏入口打开，不增加大量一级导航。
- 中文名称/搜索/关注列表；大屏主图与标的详情；资产、费用、策略、意图/订单/成交关联；刷新/错误/空态/陈旧状态。
- 模拟交易期间页面能持续查看；读页面不争账户writer、不请求付费模型、不因浏览人数增加行情请求。
- 深色风格、键盘可用、减少动效、缩放/不同大屏宽度；已知状态在中文中可解释。

### 次级增强（首期架构预留，不自动新增收费或后台任务）

- 本地收藏/排序、上次选中标的/图表周期、详情列设置；仅存非敏感偏好。
- 多标的百分比对比（最多3条、同币种/同基准/同时间范围）、成交截图导出、筛选结果CSV、页面内告警去重。
- 多市场观察作为“仅观察”折叠区域，默认不挤占原三ETF主视图；权限/币种/执行能力清楚展示。

### 本期不做

实盘开户/券商连接、手动买卖、修改风险限额、自动补仓、一键跟单、收益保证、AI聊天、新闻/社交爬取、自动学习、全市场逐笔盘口、云端账号/多租户平台、桌面原生客户端、智能体定时任务。日K/盘口/NAV/IOPV无数据时显示不可用，不能用装饰曲线补齐。

## 5. 大屏布局与导航

### 总体布局

| 区域 | 内容与大小 |
|---|---|
| 顶栏 | 左为TradeMind与账户中文别名；中为导航；右为上海时间、交易阶段、数据更新时间、运行入口、设置 |
| 固定状态条 | “真实行情 · 模拟成交”或“离线演示”；数据陈旧/连接中断时保留明确标识，不被抽屉遮住 |
| 首行 | 四张核心指标卡：总资产、今日交易盈亏、扣模型费后暂估、可用现金；冻结/持仓/费用在卡片副文案 |
| 主区 | 左侧约8列主曲线，右侧约4列当前状态/关注标的/为什么观望摘要 |
| 下区 | 最新事件与近期交易摘要；仅默认5条，高级信息进入详情 |
| 详情 | 右侧抽屉适合短详情；图表与长策略用完整页，避免多层嵌套抽屉 |

### 屏幕标准

- 1920×1080为主验收尺寸；1440×900和2560×1440均需截图。超宽最大内容宽度建议2200px居中，不让表格无限拉伸。
- 100%/125%系统缩放和浏览器缩放不遮挡主图/状态栏；图表随容器resize。
- 1366宽保持阅读，<=1024折导航与单列；手机只保证关键指标/详情可用，不将大屏表格硬缩成小字。
- 页面可垂直滚动，核心任务在首屏；禁止全页横向滚动。表格必要时自身横向滚动且固定名称列。

## 6. 中文名称与身份规则

1. 内部唯一键仍为`instrument_id`；URL、接口、筛选及图表关联继续用稳定ID，不按中文名下单或关联订单。
2. 目录包含`display_name`（简称）、`full_name`、`instrument_id`、`market`、`kind`、`currency`、别名与名称来源；只用已确认名称，未知时显示“名称待补充”并辅以代码，不编造。
3. 页面主标题/卡片/列表/提示/图例/标记/导出以中文为主，代码进入“详细信息/复制代码”；桌面可hover展示但键盘/触摸也有显式入口。
4. 同名产品用基金公司/市场/品种消歧；详情保留全称和代码，CSV保留两者，避免隐藏代码导致无法核对。
5. 全称来自现有白名单：易方达中概互联50ETF、国泰纳斯达克100ETF、华安黄金ETF；可配置显示简称“中概互联ETF / 纳指100ETF / 黄金ETF”，但必须记录简称映射与同名消歧，不全局把黄金产品混为同一只。
6. 名称接口失败只影响名称区，不能阻断账户和图表；旧映射可缓存、重新打开不闪回满屏代码。
7. 搜索支持中文/全称/代码；拼音或首字母是可选增强，先解决同名/空名/已退市/数据过期，再做模糊排序。

## 7. 页面详细设计

### 7.1 总览：先看懂今天

- 四卡各有数字、单位、口径与更新时间；未知用“— / 暂不可计算”，不能写0。模型费用不从账本现金扣，卡片注明“估算、另计”。
- 主图区支持“关注标的走势 / 账户资产变化”切换，初始显示最近选中的可用标的；顶栏中文名+价格+数据时间。没有曲线时清晰空态，不能用随机走势做背景。
- 关注卡每张展示中文名、当前价格、可信涨跌口径、小折线、当前动作中文、资金可达/仅观察、数据时效；默认三ETF，不展示虚构买入信号。
- 状态摘要回答“程序在等开市/等行情/按策略观望/等模型/退避/预算不足/需核对”，同时展示最近成功数据/策略/决策的时间。服务在线与策略可运行分开。
- “为什么还没买”显示实际最新原因，多个原因按可验证顺序列出；不能把资金不足、冷却和计划条件都归为模型不看好。
- 事件摘要按时间展示“策略更新、条件未满足、提交订单、模拟成交、数据失效”等，有详情入口。

### 7.2 行情：列表与标的详情

- 默认左侧中文关注列表、右侧详情大图；列表支持搜索/分类/仅观察筛选、名称排序/涨跌排序（只有已知口径可排序）。收藏只影响显示，不改交易白名单。
- 详情顶部：中文简称+全称入口、市场/币种/类型、价格与单位、行情来源/时间/延迟、模拟执行能力。代码低优先级，可复制。
- 主图：分时折线、1m/5m/15m K线；日K按钮按capabilities决定，缺完整日线不显示成可点击正常图。成交量独立副图、单位清楚，VWAP/均线可选；无可验证ATR等不画假指标。
- 交互：十字线显示真实时点OHLC/量，缩放/拖动、回到最新、图例开关、范围选择；新数据到达时不把正在看历史的用户强拉回末端。
- 默认不做价格平滑，数据缺口断线，午休/隔夜有明显分段；缺失分钟不能当零成交量或前值补成“真实”。
- 交易标记：仅真实模拟Fill标“买入成交/卖出成交”；意图、订单提交、撤单、程序退出分别用不同形状/图层，不将BUY计划画成成交。缩放后标记仍按实际时间对齐。
- 涨跌率：有可信前收才叫“今日涨跌”；只有首个可见点时叫“可见区间变化”，未知则不显示百分比。
- 详情侧边可切“当前计划/条件状态/持仓与成本/当前为什么不交易”。条件值有自己的as_of，不能把最新价套给过去决策。
- 比较功能最多3只同时间/同基准归一化曲线，以0%起点明确“区间表现”；不同币种不无依据合并总额。

### 7.3 资产：钱在哪里、到底赚没赚

- 账户总资产/现金/冻结/可用/持仓分别展示；cash包含冻结，不把reserved_cash再加到权益。权益=cash+market_value，估值不完整时整体标记未完整估值。
- 资产曲线与交易损益曲线切换；入金/出金单独标记，不能把1000元入金画为收益。模型已结算估值/未知预留分列。
- 今日交易损益=期末权益−期初权益−净外部资金流。收益率方法由接口声明；有外部资金流却未实现正确方法时收益率null，不能随手除初始本金。
- “扣模型费后”称暂估；pending/unknown提示未最终结算。现金仍1000与实验净结果为负可同时成立，用简单文案解释。
- 持仓表：名称、数量/可卖数量、成本价、最新价及时间、市值、浮动盈亏、占比；无持仓显示空仓，不画占比饼图。
- 费用明细：模型/角色、请求数与逻辑调用数、已知估值/待确认，给预算上限和已用；不能把上限5元写成已花5元。
- 资产页不提供入金、调限额、手动买卖；数据不完整仍允许查看历史日报。

### 7.4 策略：把AI说法变成可理解的事实

- 先看“计划有效/过期/被替换/失效/暂无”，中文趋势/风险/反证与原因；不把旧Thesis接口当快速StrategyPlan。
- 条件卡列字段中文名、比较符、门槛、当时实际值、满足/不满足/未知。entry全部满足、exit任一满足、invalidation任一失效的规则有一句中文解释。
- 分别标Flash计划、JEV动作、程序限制三个来源；JEV置信度只标“回答置信度”，不写“胜率80%”。
- 时间线：行情可见→策略可用→JEV回答→程序复核→意图→订单→成交，缺节点直接标缺档案；不能自动编一段连贯故事补齐。
- 历史按标的/日期/动作/原因筛选；“为何未交易”支持资金不足、冷却、条件不满足、数据不足、预算、模型失败、程序拒绝分类。
- 默认展示当前或最近一条，trace/model/prompt/hash/原始字段置于“技术详情”。原始字段仅白名单脱敏，不给浏览器原始供应商响应。

### 7.5 交易记录：意图不是成交

- 标签明确分“决策 / 订单 / 成交 / 资金变动”，默认成交；无成交时空态提示可去看决策与原因，不用计划条目填满成交表。
- 中文名称/方向/状态/时间/价格/数量/费用/原因是默认列；长ID隐藏到详情并可复制。
- 筛选日期、标的、方向、状态；服务端分页/游标，限制每次条数，切筛选回第一页，页数/下一页保持一致。
- 订单详情支持部分成交、余量、撤单/过期/未知与资金冻结；同一订单多Fill不重复累计费用，权威费用以账本事件/Fill修复后的契约为准。
- 点击关联可跳到该时段图表或策略，不把当前状态覆盖历史状态；无关系明确未留档。

### 7.6 日报：能复盘与导出

- 今日/日期选择、盘中暂报/日终、账户与数据截至时间；日切按Asia/Shanghai，不按浏览器所在时区偷换。
- 资金变动、交易损益、模型估值、成交、策略与限制摘要；金额完全复用日报口径。
- 历史缺失/生成失败/部分数据有专门状态；不能把空报告当今天无交易。
- JSON/CSV/Markdown/打印至少先支持已有格式的浏览和安全下载；客户端导出显式范围与时间，CSV处理公式注入，敏感字段不导出。
- 不为生成新中文总结追加模型调用；使用已有说明和确定性文案。

### 7.7 运行中心与高级设置

- 页面顶栏入口打开运行中心，展示监督进程、paper worker、数据/模型/预算状态的分项结果；健康心跳不等于策略正常或已成交。
- 区分“等待开市/午休/收盘、行情热身、数据陈旧、模型请求中、有效观望、退避/额度耗尽、锁定待核对、服务断开”。展示下一次动作计划时间（只有后端有值才展示倒计时）。
- 告警按类型+标的+原因去重，事件首次/最后时间与次数可见；不让每5秒同一WAIT弹一次通知。初期仅页面内，不发短信/邮件/桌面系统通知。
- 控制令牌和动作只在高级面板；无能力/无令牌时明确“当前只读，不可操作”。不在localStorage/URL/日志保存令牌。
- 只读常驻服务不初始化交易Pipeline来临时执行控制。现有授权操作若后端不可达，则禁用并解释，保留旧授权工作流入口；不新建危险IPC。
- 暂停新风险、解除保护等既有动作必须由后端实际能力声明、需要的令牌与明确反馈支撑，错误/超时不能弹成功。解除保护不能自动处理UNKNOWN对账。

## 8. 数据与只读API契约（拟新增，实施前冻结）

新路由置于`/api/workbench/`，旧`/api/*`保持兼容。只读API不得依赖`get_pipeline`、`ensure_account`、收费provider、迁移或writer租约；缺配置/库不自动创建账户。服务端固定本实验账户，前端不能任意传account_id浏览别的账户。

| 建议端点 | 用途 | 数据来源与限制 |
|---|---|---|
| `GET overview` | 四卡/运行摘要/更新时间 | 同一只读事务的账本状态、日报/健康快照，声明as_of与一致性 |
| `GET instruments` | 名称目录/能力/列表 | 已核验白名单+已有观察元数据，来源/未知明确，不能由名称推断交易资格 |
| `GET instruments/{id}/bars` | minute/K线/量/指标 | 只读已存Context分钟事实；按时间/可见版本过滤；无则partial/unavailable |
| `GET instruments/{id}/events` | 图表上的意图/订单/Fill | 账户隔离、事件类型/时间分开，且与bars数据范围一致 |
| `GET account/series` | 权益/交易损益/费用曲线 | 账本事件+可见估值/日报，禁止靠线性插值伪造历史权益 |
| `GET positions` | 持仓详情 | 当前账本与可见估值，现金/冻结不重算两次 |
| `GET strategies` / `strategies/{id}` | 有效计划/条件/历史 | strategy_plan_history/coalesce与关联Context，不凭新行情补旧判断 |
| `GET activity` / `activity/{id}` | 决策/订单/成交/资金分页 | account_id严格过滤、type白名单、参数校验，返回cursor/has_more |
| `GET runtime` / `alerts` | 只读运行/预算/告警 | 已存健康/状态/审计分类，不扫描所有历史payload或输出原始异常 |
| 既有`/api/reports/daily/{day}`的只读适配 | 日报与下载 | 复用计算口径；新只读服务优先读已生成产物，缺失不调用模型/创建账户 |

公共信封建议：`schema_version/account_alias/as_of/generated_at/data_status/source/age_seconds/stale_after_seconds/partial/missing_reasons/data`。响应是快照不是推送承诺。`Decimal`金额/价格/数量均字符串，null与0分开；服务器带时区时间统一，浏览器显示上海时间。

`data_status`区分ok/partial/stale/unavailable/error；UI请求loading/refreshing与业务状态分开。价格/权益未知不着色成涨跌。接口版本/contract测试必须先于页面依赖冻结。

### 曲线的硬性要求

- 不因GET浏览触发免费行情请求或缓存回源，更不触发模型；已有后台记录可读多少就展示多少。
- Context分钟数据按`instrument_id + bar_time + 可见版本`去重，`available_at <= as_of`先过滤，再选可见修订；不能只取最新修订后过滤丢掉已知旧版。
- 默认1日，允许范围必须由能力返回；原始单请求建议最多2000点、上限5000，范围/period白名单与游标需服务端限制。具体性能基线在Task冻结，不能无限扫库。
- 5/15m按交易时段边界聚合，开高低收/量额规则固定，只有完整闭合窗口称完整K线，缺分钟标partial；午休/隔夜不跨段凑根数。
- 稀疏Context只有“本地可见记录曲线”，不能叫“全天完整市场行情”；日K需要完整权威数据，不能把若干分钟拼成完整一天。
- 下采样只影响展示，保留极值与事件时间，原始数据可查；金额/损益不在浏览器用浮点累计作为权威结果。
- 新图表数据持久化/缓存若确需增加，必须明确写入Owner/来源/保留期/容量/迁移与交易进程影响，先更新ARCH-027；首期优先读取现有存量，不新建行情采集调度。

## 9. 刷新、错误与空状态

- 首屏每资源一次，顶层一次协调；status/概要可5～10秒，图表只在新bar/选中切换时更新，后台页暂停/降频；频率最终以真实性能基线冻结。
- 单资源最多一个在途请求，超时取消；切标的/日期/页面撤销旧请求，旧响应不能覆盖新选择；错误指数退避并有上限，不自动重试POST。
- 一块失败只影响该块；保留最后成功快照并明确时间/陈旧，不用旧数据冒充更新成功。Abort不是错误弹窗。
- 骨架屏只在首次未知时显示；空仓、无订单、尚无计划、缺bar、接口离线、部分估值、预算耗尽各有独立说明和可执行的查看入口。
- POST等待/成功/失败/未知结果均可见；超时后只读核对实际状态，不能自动再发一遍或默认成功。
- 不输出原始服务器异常HTML、数据库路径、认证头到用户界面；错误仅分类中文文案和可复制的脱敏追踪标识。

## 10. 技术路线建议与边界

建议Vue 3 + TypeScript + Vite，ECharts按需模块、本地打包；现有项目没有前端Node工程，不能说已经具备该技术栈。Node/包版本由26-03执行时按官方支持范围冻结并锁文件，不在规划里猜最新版。

- Vue用于组件/状态，TypeScript用契约减少空数据错误；Vite只做开发/构建，生产仍由FastAPI同源提供构建静态资源，不跑Node/Vite生产服务。[Vue官方说明](https://vuejs.org/guide/typescript/overview)、[Vite构建](https://vite.dev/guide/build)、[Vite静态交付](https://vite.dev/guide/static-deploy.html)。
- ECharts统一分时/K线/量/权益图和缩放；默认Canvas，必须按实际点数/屏幕验证，不能只因库支持就宣称性能通过。生产不依赖CDN。[ECharts渲染说明](https://echarts.apache.org/handbook/en/best-practices/canvas-vs-svg/)。
- 前端目录建议`frontend/`，产物在`src/trademind/api/static/workbench/`。Python包数据要包含递归JS/CSS/字体，不能只在editable本地能打开。
- hash导航避免抢占`/api/`和`/reports/`；保留旧页面回退入口，不直接删原单页。
- 常驻观察进程与paper writer职责分离，缺库/数据时正常显示不可用，绝不启动交易writer来“修好页面”。
