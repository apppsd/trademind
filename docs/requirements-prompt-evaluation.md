# 提示示例、评测与版本管理需求

实施Checkpoint：04～06工程完成，证据见[报告](research/20261011-prompt-eval-verification.md)；07/08真实依赖未满足，09条件后置。以下为完整目标契约，工程测试不代替真实效果。

## 目标与范围

让提示词修改有固定输入、明确断言、失败原因和可回滚版本，供执行会话逐项完成。基于[公开调研](research/20261011-prompt-engineering-practices.md)，本文件为新增需求，不代表已实现。实际当前能力以[当前状态](project/current-status.md)和源码为准。

保留[快速决策需求](requirements-jev-fast-decision.md)及[T0模拟盘边界](requirements-t0-shadow.md)：deepseek-flash低频生成StrategyPlan，TypeSafe JEV四题快速判断，程序计算数量/硬风控/模拟执行；500元隔离paper、已核验ETF、无做空/杠杆/实盘。旧链保留对照。

## 使用流程

执行者补合法示例 → 为固定场景标允许/禁止行为 → 保存模型响应或读既有档案 → 离线评测 → 分类分析失败 → 修改一个提示因素 → 同输入再比较 → 通过真实留出门槛后显式选版本 → 核对实际运行版本 → 必要时回滚。

离线评测默认只读，不生成模型响应、不联网、不产生订单。不完整响应只能用于报告缺失覆盖，不能推算模型会如何回答。

## 功能契约

### F1 合法示例
flash策略提示包含紧凑的完整输入/九字段输出配对示例，覆盖无机会WAIT与有仓退出。值与条件来自示例输入和生产Schema，不能复制固定阈值到实时策略。JEV仍用Choice/Noul专用题型，不套聊天JSON草稿。详见TASK-20261011-04。

### F2 固定案例
不少于24例，至少10类正常/异常场景，涵盖合理BUY、WAIT、有仓退出、数据/费用/时间、恶意文本与重复执行。标签说明依据及允许动作集合，模型建议、程序Guard和OMS结果分别标注；数据集/标签版本可追溯。详见05。

### F3 离线报告
输入为固定案例清单及已有响应，输出原子JSON和Markdown。分别报告请求失败、契约失败、危险建议、实际放行、机会/退出覆盖、延迟及费用；每项带分母，缺失值为unknown/null，不记零。报告为pass/fail/incomplete，含输入/提示/模型/配置指纹。A/B只比同输入同标签，动作不同不自动判错。详见06。

### F4 真实失败档案
复用原Task17采样和归档，最小化扩展字段，记录失败阶段/原因、可脱敏结构化输出、模型建议及程序结果。旧档案缺字段明确不完整；不存密钥、全量配置或未经白名单的原始请求/异常。生产预算和账本保持原单写者，不给评测器写权。详见07。

### F5 版本选择与回滚
基线、候选、运行版本和指纹明确。合成案例安全硬约束零失败，并覆盖合理BUY和退出，防止全WAIT骗过评测；真实门槛在查看留出结果前冻结。原Task08负责真实标签与时间切分，样本不足不晋级。版本选择显式，容器运行须核验镜像与提示哈希；回滚不重置账户、持仓、预算、预约或订单。详见08。

### F6 有条件的自动优化
原生评测和真实档案足够后才评估Promptfoo/DSPy GEPA。先出收益/兼容/费用/维护对比，再决定是否做有界原型；有依据地不采用也是有效结果。优化不能改Schema/模型/硬风控，也不能进入实时热路径。详见09。
