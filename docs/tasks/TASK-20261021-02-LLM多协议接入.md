# TASK-20261021-02 LLM 接入层多协议支持

## 背景与需求（用户 2026-10-21 提出）

用户要求大模型相关内容支持四类接口协议（截图为中转站协议选择器）：

- Anthropic Messages（原生）
- OpenAI Chat Completions（需开启路由）
- OpenAI Responses API（需开启路由）
- Gemini Native generateContent（需开启路由）

"需开启路由"为中转站侧说明：同一模型经由中转以不同线协议暴露，TradeMind 侧按所选协议适配请求/响应。

## 范围

- 新增协议适配层 `src/trademind/models/protocols.py`：四协议的请求构造（URL/认证头/payload）与响应解析（文本/finish 原因/usage token）归一为单一 `ProtocolReply`。
- 泛化 LLM provider：`DeepSeekProvider` → `MultiProtocolLLMProvider`（保留 `DeepSeekProvider` 别名，runner/prompt_experiment 的 isinstance 检查与既有测试不受影响）。
- 配置面：`[llm] protocol`（默认 `openai_chat` = 现行为）；env `TRADEMIND_LLM_PROTOCOL`；管理页白名单新增 `llm_protocol`（枚举校验）。
- 审计：`ModelCall.provider` 仍为 deepseek 枚举，`model_params` 记录 protocol；诊断键维持 `SAFE_DIAGNOSTIC_KEYS` 白名单不扩。
- 离线测试：各协议请求形状/响应解析/失败分类（refusal/length/protocol_error）/修复轮/预算。

## 非目标

- 不改 JEV：TypeSafe 官方协议为冻结契约，多协议仅针对 flash 策略 LLM（`llm.*`）。
- 不改模型锁定：T0 profile 仍强制 `llm.model='deepseek-flash'`；协议与型号正交，切换协议不构成换型号。
- 不引入 per-vendor SDK：沿用项目无 SDK 依赖的原生 HTTP 风格（与现有 DeepSeek / TypeSafe JEV adapter 一致），Anthropic Messages 按官方 HTTP 契约实现。
- 不做真实付费调用验证：全部离线 mock；真实验证需用户明确授权。
- replay/shadow 隔离与 stub 路径不变。

## 可验证验收标准

1. 四协议各能离线完成一次 `complete()`（mock HTTP）：审计 ok、usage/诊断归一、finish_reason 映射正确。
2. 各协议失败形态正确分类（explicit_refusal / length_truncated / invalid_json / protocol_error / http_error / rate_limited）。
3. openai_chat 现行为不变（thinking / response_format / max_tokens / DailyModelBudget 路径既有测试全过）。
4. protocol 非法值在 `load_config` 拒绝；`TRADEMIND_LLM_PROTOCOL` env 与管理页 `llm_protocol` 覆盖生效、枚举外值 400。
5. base_url 缺省或仍为 DeepSeek 默认时按协议取官方默认端点；自定义中转 URL 原样保留。
6. 全量 pytest 通过；`check_docs.py` 0 错误。

## 计划

1. `config.py`：`VALID_LLM_PROTOCOLS`、`LLMConfig.protocol`、env、admin spec+enum、`_validate_llm_protocol`。
2. `models/protocols.py`：四协议 `build_request` / `parse_response` / probe / `effective_base_url`。

5. `tests/test_llm_protocols.py` + `tests/test_admin_settings.py` 补充；文档同步。

## 实施记录（2026-10-21，Claude Code）

- `src/trademind/models/protocols.py`（新）：四协议适配层。`effective_base_url`（base_url 空/DeepSeek 默认 → 协议官方端点；自定义中转 URL 原样）、`session_headers`（Bearer / `x-api-key`+`anthropic-version: 2023-06-01` / `x-goog-api-key`）、`build_request`（openai_chat 独有 thinking/response_format；anthropic `max_tokens` 必填、无预算上界时 4096、system 顶层；responses 用 `instructions`/`max_output_tokens`/typed input；gemini 用 `systemInstruction`/`generationConfig`、assistant→model 角色）、`parse_response`→`ProtocolReply`（文本拼接、finish 原因映射、refusal 判定、usage tokens 与缓存/推理/总数归一、结构错误；诊断键不扩 `SAFE_DIAGNOSTIC_KEYS`）、`probe_request`（gemini 列表剥 `models/` 前缀）。
- `src/trademind/models/deepseek.py`：类泛化为 `MultiProtocolLLMProvider`，`DeepSeekProvider` 保留为别名——runner/prompt_experiment 的 isinstance 与既有测试调用不变；共享管线（熔断、DailyModelBudget reserve/reconcile、一次 JSON 修复轮、拒绝/截断/协议错误诊断、审计）原样保留；`call.model_params` 增记 `protocol`；probe 按协议取模型列表端点。
- `src/trademind/config.py`：`VALID_LLM_PROTOCOLS`、`LLMConfig.protocol`（默认 openai_chat）、`_apply_env` 增 `TRADEMIND_LLM_PROTOCOL`、`_validate_llm_protocol`（在 env/管理覆盖应用之后校验，非法值 ConfigError）、管理白名单新增 `llm_protocol`（enum 校验，非枚举 400）、`describe_admin_settings` 返回 `choices`；"DeepSeek Base URL" 标签更名 "LLM Base URL"。
- `src/trademind/models/provider_factory.py`、`src/trademind/runner.py`（探针）、`models/__init__.py`：传参/导出。
- `src/trademind/api/static/index.html`：管理页说明补充四协议取值与 base_url 解析规则。
