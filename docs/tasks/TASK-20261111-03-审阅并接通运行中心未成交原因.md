## 审阅结论

主链的门禁、租约、Guard 否决和只读观察分层是清楚的。差的部分主要是后来的展示和旁路没有跟已经写好的事实对齐，不是交易公式被写坏。

已核对、这次不改的点：

- 动态 SQL 的表名和列名来自闭合元组或内部行字典，不是请求参数。`workbench_charts.events_response`、`Repository._insert`、`paper_run` 水位查询都属于这一类。
- 没有把密钥写进源码。模型密钥仍从配置读取。
- `except Exception` 多出现在审计落盘、通知、监督器状态读取。交易拒绝本身仍抛 `NotFresh` / `GuardVeto`。纸面撮合在行情路由失败时返回空列表，这是既有的「不确定就不成交」。
- 逐条条件真值 `condition_truth_rows` / `action_gate` 已经在快速链、健康和日报里。功能地图原先写成「还没落到健康和日报」，那句过时。
- 未接到运行的部分仍是：记忆 `mature` / `reflect` 没有生产调用，股票选择器只在测试里构造，多资产 `execute_order` 默认拒绝，驾驶舱左窗没有固定主机时保持样例。
- 最长的函数是 `read_intraday_health`、`generate_report`、`pipeline._run_decision`、`guard.check`。它们现在不适合和这次展示修复一起拆。

这次改的断线：`record_progress` 写入 `last_blocker_class`、`last_decision_reason`、`last_action_gate`。`read_intraday_health` 会读这些键并给出中文。工作台 `runtime` 却只取 `blockers`、`budget_meta` 等进度文件里没有的名字，运行中心因此一直显示「无阻断项记录」。
