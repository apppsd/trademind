# TASK-20261022-03 修复本地停止误启动与强停锁定丢失

## 2026-10-22独立复验退回（Task22-04）

59项相关测试独立通过，原stop误启与强停halt丢失两项修复有效。但shutdown未核验paper在等待期间退出后的排空报告，报告缺失/结果未知仍持久化halted=false，原验收要求未完整满足。Issue22-01重开，本Task退回in_progress，Owner仍为Claude Code；下方completed为此次复验前记录。

## 2026-10-22第二轮修复（shutdown最终报告核验，交Task22-04复审）

`shutdown()` 排空后对 paper 轮的 `report_path` 执行 `result_policy` 分类：读取失败按空报告（缺失/损坏）、status=failed、model_pending/worker_active → 置 halted 并以该原因持久化；合法终态（completed 且已排空）不置 halted；任何路径都不清除既有 halted/原因。`scripts/run_local.py` 无需联动。新增回归 2 项（missing/unknown/error/clean 四类对照 + 既有 halt 不被合法报告清除），lifecycle 29 项 + supervisor 19 项通过；**Task22-04 隔离片段逐字复跑转绿**（missing expected=True actual=True、unknown True/True、classifiable False/False）。

## 背景

[Task22-02](TASK-20261022-02-独立复验本地双模型运行收尾.md)独立复验确认真实行情、6份DeepSeek策略、2次探针、1000元账户及收盘排空，但在隔离FakeChild环境复现两个停止缺陷，见[Issue22-01](../issues/ISSUE-20261022-01-本地停止流程误启paper且强停状态未持久化.md)。现有52项相关测试全部通过，未覆盖这两个反例。

1. serve活跃时收到stop：tick将desired置None，仍执行start(None)，构造新t0-paper命令且kind变为None。停止操作反而可能启动交易worker。
2. run的finally强停paper：仅内存halted置true，状态文件可能仍false，重启丢失“结果未知，需人工核对”的门禁。

## 需求

- 保留当前真实行情、双模型、1000元账户、预算、Guard/OMS和既有排空政策；修复不制造任何交易。
