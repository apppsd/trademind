## 背景
用户明确要求后续交易日能够完成交易，而不只是看到容器healthy或大量WAIT。今日运行事实和零成交归因分别见Task13-08、13-09；空输出、盘中健康、预算差异和收盘锁定根因只在对应Issue维护，本Task不复制。

## 需求
1. 在首个准备条件满足、且项目交易日历确认有效的后续交易日，正常进入早盘/午后模拟循环；目标不是等到尾盘才出现有效策略。
2. Flash能够稳定生成合法中文StrategyPlan；满足自然交易条件时，JEV能输出真实动作，程序完成合法数量、Guard、OMS、模拟撮合与资金持仓对账。
3. 处理未消费模型结果导致的收盘锁定，避免未处理风险阻断下一交易日；安全锁定不能靠删除状态或无条件重启解除。
4. 提供明确的交易就绪状态和零成交原因，区分行情/模型失败、合法观望、资金或最小单位不可达、风控拒绝与异常锁定。
5. 交付真实模拟BUY→SELL→清仓证据；既有真实闭环任务TASK-20261009-09及Issue07-14引用本轮证据，但各自按原标准验收，不自动完成五日观察。

## 不包含
- 仅限既有三ETF、现有1000元paper账户；不接券商、不下实盘订单、不保证盈利。
- 不承诺每个交易日必有成交；市场或合法策略要求WAIT时必须保留观望。
- 不为了成交扩大资金、放宽风控/时段/数据门禁、替换模型、禁用JEV、清零预算或注入BUY/SELL。
- 不把空文本、原始推理内容、过期计划、fixture、mock或回放结果冒充真实模型/实时行情。
- 本次只授权落任务文档；未来收费调用、重建/部署、停止/恢复运行须核对既有授权是否覆盖本次操作、预算及范围，未覆盖先请求明确授权。

- [ ] 每只观察ETF记录新鲜度、完整窗口、交易单位、手续费后最低购买成本，以及现有现金/敞口上限下是否可买。至少一只具有合法数量可达性，否则明确资金/标的限制，不宣称可交易。
- [ ] 最终容器源码/提示/配置指纹与验证版本一致；只看宿主文件修改不能通过。原代理、数据挂载和账户保留，单writer无冲突。
- [ ] Flash/JEV能力、剩余请求/费用及未知费用预留均满足启动标准；沿用现有预算，不在闭市先做收费探针。

### B. 有效策略与动作链
- [ ] 原13-04/05/12-05已按证据完成并通过独立复核，不仅根据Agent完成声明或旧回归数量判断。
- [ ] 后续真实盘中至少两个不同策略刷新时点得到合法中文计划并写history，错误/截断/空输出分类准确；两个纯WAIT计划只能证明策略接口可用，不能证明买卖闭环完成。
- [ ] 正常缓存/刷新/冷却不永久饿死某只标的；逐标的记录最近有效计划、下次可评估时刻。若发现不公平调度缺陷，先建Issue/明确范围再修，不靠取消全部冷却增加收费。

- [ ] 模型故障/预算耗尽/新仓冷却不能阻断已有持仓的确定性风险退出；正反例分别验证。

### C. 收盘锁定与次日恢复
- [ ] 定位Issue13-03对应的退出/排空边界，用可复现测试覆盖截止时点到达、已有结果未消费、worker仍活跃、超时、过期结果和账户版本变化。
- [ ] 停止新请求后，对安全可丢弃的过期/失效结果记录明确终态；对需要消费的结果按原账户/时点规则处理。不得执行过期新仓、重复订单，亦不得静默删除未知结果。
- [ ] 有未排空worker、未知订单或资金状态时继续锁定；仅在worker结束、订单/资金对账通过且结果都有明确终态后，允许经审计的安全恢复。
- [ ] 跨午休、正常收盘、次日开盘、容器重启分别验证状态恢复；正常无残留收盘不误锁次日，异常残留不能随交易日切换自动清除。
- [ ] 现有锁定只能在有明确授权、停/排空确认及账户对账后处理；不能直接将halted改false当修复。

### D. 真实模拟交易闭环（完成硬门槛）
- [ ] 在后续实际交易日，由自然符合条件的真实Flash策略和JEV动作触发至少一次合法BUY，经Guard/OMS形成订单和模拟成交，不人工塞信号。
- [ ] 同一持仓产生合法SELL并模拟成交，完成该轮清仓；保留账户、run_id、trace_id、行情时点、计划版本、JEV答案、数量/费用、Guard、订单、成交和持仓变化证据。
- [ ] 撮合使用提交后才可见的合格行情，不用未来数据或决策时已知收盘价回填成交；没有合格报价不能伪造成交。
- [ ] 账户现金/冻结/持仓/权益及交易费用可对账；请求计数、调用审计、未知费用与配置估值闭合或逐项解释，不把估值当供应商账单。
- [ ] 该轮结束后无未确认订单、未消费结果或活跃worker，自动服务回到明确可恢复状态；页面/日报可读，包含本轮真实订单和成交。
