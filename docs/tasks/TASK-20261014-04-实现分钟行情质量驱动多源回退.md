## 2026-10-15 修复：Issue15-01四项工程缺口（实施记录，缓存分支待补）

[Issue15-01](../issues/ISSUE-20261015-01-跨源观察一致性与时间预算门禁不完整.md)四项缺口全部修复，仅改 `market/router.py` 与 `tests/test_minute_source_routing.py`；基础回退/缓存/限额行为不变，`get_minute_bars` 对外签名不变，builder/pipeline/runner/配置无需改动。

修复语义（对应Issue关闭条件，全文见该Issue"最终解决方法"）：
1. **差异拒绝不再被改选洗掉**：新增 router 级 `self._divergence`（instrument→note/observer）。观察超容差时记录该状态；后续pref候选与再次请求在合格后仍被该状态拒绝——note写入`report.limit_violations`（下游据此拒绝新风险）、加入rejections、**不缓存**，直到一次合格且一致的观察将其解除（一致观察同时解除状态并正常选定/缓存）。非零interval与每日限额边界均覆盖：观察被interval/预算/cap/观察源不合格压制时，既有拒绝状态持续生效。
2. **观察共用整轮预算**：`_maybe_cross_check` 增加 `deadline/as_of/quote_max_age_seconds` 参数。观察等待钳至 `min(per_source_timeout, 剩余预算)`；剩余预算≤0时记 `status=skipped`（不发起请求、不消耗 last_mono/count/requests）；超时弃置worker只写`_bounded_fetch`本地box，不影响路由状态，观察源不记退避。
3. **首次观察显式建模**：`last_mono` 初值 `0.0`→`None`（从未观察必观察）；间隔门控仅对已有观察生效。router时钟改为实例属性 `self._clock`（默认 `time.monotonic`），测试可注入可控时钟；既有真实时钟行为不变。
4. **观察沿用候选接受策略**：观察源结果按同一 `as_of` 可见性过滤（`available_at<=as_of and bar_time<=as_of`）、同一 `normalize_minute_bars(as_of=...)` 质量检查（`_rep.limit_violations` 已检查）、同一 `quote_max_age_seconds` 新鲜度判定；不合格观察记 `status=unqualified`（reason=empty/quality/stale），不比较、不算一致、不解除既有拒绝；无重叠时间视为不确定，也不解除。

附加设计修正（5）：差异拒绝**不再对候选源记退避**。责任在候选与观察源之间不明确，持续拒绝由instrument级`_divergence`承担，请求消耗由每日限额约束；否则差异会通过退避使单源对其他标的沉默并可能把双源都推入退避后以RuntimeError收场。空/陈旧不退避的既有原则（修正1）同理。

测试（tests/test_minute_source_routing.py，17→24项）：新增7项——`test_cross_check_divergence_refusal_survives_pref_and_rerequests`（900s间隔下round1差异、round2再请求仍拒不缓存、interval到期一致观察解除并缓存）、`test_cross_check_daily_cap_and_day_switch_do_not_launder_divergence`（cap耗尽仍拒；北京日切换重置计数、重新观察仍不一致仍拒）、`test_cross_check_observer_waits_within_round_budget`（修复前约0.297s，现0.1s预算内；观察源无退避污染）、`test_cross_check_skips_observation_when_round_budget_spent`（预算耗尽零请求零消耗）、`test_cross_check_first_observation_independent_of_monotonic_value`（时钟值10<interval=900仍观察，即复核反例）、`test_cross_check_future_visible_observer_not_a_comparison_basis`（修复前6.67%差异，现unqualified且无拒绝状态）、`test_cross_check_stale_and_invalid_observers_not_a_comparison_basis`。既有 `test_cross_check_sparse_interval_and_agreement` 改用FakeClock确定性覆盖初始/间隔内/间隔后（原实现下该测试在复核环境实际失败，即缺口3）；原interval=0差异测试保留（掩盖缺口1的原因，现由900s间隔测试补齐）。

实施中的设计修正（与 Issue 复现时的初步方案差异，均已记录到 ARCH-020 附录）：
1. **空窗口/陈旧不触发源级退避**：它们是 (instrument, window) 属性而非源健康属性；退避仅由传输异常与质量违规触发。否则单标的临时空结果会让该源对后续标的沉默 60s，破坏重放语义。
2. **无 as_of 的取数路径不过滤 available_at**（TASK-08 既有语义：可见性过滤归缓存命中规则与调用方）；仅当调用者传入 as_of 时按 `available_at <= as_of` 过滤。
3. **缓存命中重验**：过滤后为空且无 as_of → 空结果即缓存合法答案（重放"available 后才复用"语义）；非空但陈旧/质量失败 → 穿透重取。
4. **轮预算被钳制的源超时 = 本轮时间耗尽**：不再对后续源发起注定超时的请求。
