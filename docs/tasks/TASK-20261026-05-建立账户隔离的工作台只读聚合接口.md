## 需求与解决方法

1. 先冻结需求第8节信封、账户固定策略、金融字符串/null/时间语义、业务data_status与capabilities；示例分别覆盖正常、空仓、未知估值、部分档案、未初始化。
2. 以mode=ro/query_only构建短一致性读取，不走项目Database迁移/ensure_account/provider。活跃WAL库不能用immutable偷懒；缺库/未知Schema安全返回，不创建任何文件或writer租约。
3. 实现overview/positions/strategies/activity/runtime/alerts所需最小查询，依据account关系过滤；没有可归属account的旧model_calls不默认归本账户，明确scope/unknown。
4. overview复用账本/日报口径，现金含冻结、模型费另计；多块返回as_of/version/age和缺失原因，允许部分可用，不以单个坏源清空所有卡片。
5. activity提供类型/日期/标的/状态白名单、limit上限、稳定cursor与has_more；所有id详情验证归属，不能凭id取别的账户。有效StrategyPlan从真实计划history/cache读取，不用Thesis代替。
6. runtime返回观察/交易/策略/数据/模型/预算各自状态和后端能力，不通过新只读app启用控制。中文文案用确定性映射，原始异常/供应商响应不返回。
7. 用有界缓存/查询索引解决性能，若确需数据库迁移，先协调存储Owner、记录架构，迁移不能在GET中发生。
