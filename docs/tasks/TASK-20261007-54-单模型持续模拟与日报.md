## 背景与需求

用户要求先放下JEV，用已通过最小真实探针的DeepSeek推进代码任务。[需求](../requirements-t0-shadow.md)、[ARCH-002](../architecture/02-t0-etf-shadow.md)定义单模型优先阶段。以下均未实现。

1. 新增验证过的T0实验命令，独立paper账户/库/run；按真实日历和连续交易时段每分钟检查行情，不强迫每分钟调用AI。有界队列、持仓优先、合并触发与开仓冷却。

2. 运行控制区分暂停新增仓位、退出实验与全局紧急停止；定时止损/到期/收盘退出不受DeepSeek预算/冷却阻断，但有效行情缺失不能假成交。收盘停止新风险，优雅停止持久状态。

3. 调用计数和费用预算包括全部角色、汇总、重试与修复，跨重启同日持续。超限/断网/服务错误熔断，未经确认不继续消耗额度；未知费用标unknown，不能按0。

4. 页面显示JEV+deepseek-flash、实际JEV状态、真实/延迟行情、模拟成交、run和账户、行情更新时间、各角色延迟、预算、持仓/冻结/拒绝/故障。控制接口沿用token鉴权，不将模型Key给前端。

5. 日报记录计划与有效评估tick、缺口原因、各动作与订单/成交、费用、已实现/未实现损益、回撤、未平仓及恢复事件。模拟成交价已含滑点/价差不再重复扣；模型费用独立再扣得到实验总结果。

6. 历史存档支持不调用外部服务的隔离回放；配置/模型版本变化必须新run，恢复前验证指纹。报告明确双模型实际版本，JEV增益未独立检验时写not_evaluated，不能把接通称增益。
