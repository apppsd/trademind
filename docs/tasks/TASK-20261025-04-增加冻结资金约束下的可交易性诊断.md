## 问题与需求

本地1000元余额仍受300总仓位/200单证券/100现金储备约束，三ETF中部分价格乘100份已超200。此前旧容器900限额的结论不能套用本地账户。需要让执行者能回答：哪个标的当前可观察、哪个至少可买一手、被哪个限制挡住，而不是靠加钱或放宽风控换成交。

## 解决方法

1. 输入显式本地JSON快照：account_id、as_of、cash/reserved_cash、positions与已有挂单、各标的价格/来源/可见时间、规则版本、资金限额。默认不加载.env、不启动Pipeline/项目Database、不联网；可选SQLite只允许URI mode=ro且输出字段白名单。快照缺失不默读运行密钥或猜值。
2. 按核验profile取lot_size、T0资格和模拟FeeSchedule，输出一手市值/买入手续费/现金成本，账户可用现金与剩余单标的/总敞口。资金冻结按账本语义扣一次，说明未成交买单承诺，避免重复或漏计。
3. 检查价格有效/陈旧、整手、单标的上限、总上限、现金储备及费用；支持多个同时约束原因。显示“资金可达/仅观察/数据不足”，资金可达不等于交易授权，模型、时段、质量与Guard仍是后续门禁。
4. 用源快照区分本地与旧容器实验；不得由CLI绕过真实门禁。保持原三ETF观察池，生成可交易子集供解释，不自动删标的、不自动改资金/限额。
5. 给出接受当前限制的结论：不可买标的仅观察，闭环验收落在自然信号及资金可达标的；若用户要改池/资金，列清所需条件作为建议，未确认前不执行。

## 不包含

不重写生产Sizer，不缩小申报手数，不硬编码某ETF永久可买/不可买，不将缺行情当零，不用历史价格冒充当前，也不以理论可买认定模型必买。
