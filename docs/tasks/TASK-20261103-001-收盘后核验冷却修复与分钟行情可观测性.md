### 本地源码校正

1. `pipeline.py`：缺bars/freshness时抛NotFresh；分钟特征不完整时先返回WAIT_DATA_QUALITY，不进入付费策略/动作worker；WAIT_MODEL_PENDING仅表示本轮没有可消费的异步模型结果，不是模型已决定WAIT或请求一定在HTTP中。NotFresh也可来自参考报价、异步结果过期或账户/条件变化，需保留安全的细分原因，不能只凭异常类归为同一故障。
2. `runner.py` 的结果摘要将error截为异常类；`paper_run.py`用该NotFresh/preflight blocker/WAIT_DATA_QUALITY归类“行情不足”。health是带优先级的综合状态，heartbeat推进只证明循环活着；active_plan_count=3不证明当前行情完整或计划条件可执行。
3. `context/builder.py`按最新bar_time判断年龄，门槛为min(180, quote_max_age_seconds)；约106秒本身未超180秒。`context/features.py`只用最新连续1m片段，午休/隔夜/缺行会重置：ret_15m需16根，atr_14需15根。14根缺特征与年龄超限是两类问题，不能放宽年龄门槛掩盖断档，也不能断言下午14:14仍是相同缺口。
4. `runner.py`预检在没有任何一个标的同时满足完整/新鲜条件时给出fresh_complete_minute_data_unverified；该总blocker不能证明每个标的都超龄。需按标的、采样时点记录缺字段和可用连续根数。
5. 全局模型窗口使用`fast-eval:<account_id>`与`t0.fast_eval_seconds`，不是旧链逐标的`t0-candidate`的candidate_cooldown_seconds。两者默认均300秒，单凭后者的配置值不能确认快速链实际窗口值。命中已有冷却的tick不滑动续期。
6. `reports/daily.py`的decisions取去重后的已保存intent（按decision_id/intent_version）；619不等于全部检查轮次、所有NotFresh或所有模型HTTP请求。535+81+3=619，只是这一分母的首个返回原因分布；13:15日报与14:14–14:17 health不可拼成同一时刻证据。81 no actionable不调用JEV；3 uncertain表示证据/计划或动作置信未过门槛，不是系统要求成交。
7. 32/100、26/30尚未达到所报次数上限；策略角色额度已接近上限。成本预留、其余角色、重试/失败与当时实际拒绝需另核，不能凭次数断言全部预算可用，亦不能将“预算耗尽”列为已证实主因。

- **当前推进优先1：分钟行情完整性/新鲜度。** 这是模型链前置硬门禁，13点已有连续根数缺口，14点仍报告NotFresh/行情不足；足以升为独立的首要排查项，但具体NotFresh子因尚未证实。先区分午休后正常暖机与持续断档/延迟，不能仅据13:00–13:15暖机窗口宣告数据源故障。

- **优先3：实际计划条件不满足/JEV不确定。** 分别81/3条；只有行情合格后才核对条件真值与审计请求，不能当成必需修成BUY的缺陷。额度接近上限是约束，不靠提高额度解决。

### 3. “no actionable strategy conditions”精确解释

直接返回点：`src/trademind/agents/fast_decider.py:FastDecider.decide`先检查计划/上下文期限，再在`len(state.allowed_actions)==1`时返回该字符串、WAIT、空answers，**不调用`jev.evaluate`**。合法状态唯一动作就是WAIT；这不是JEV的市场判断，也不是额度/冷却原因。

动作集合来源是`src/trademind/context/fast_state.py:build_fast_state/conditions_allow`及`src/trademind/domain/strategy.py:Condition.matches`：

- BUY须计划允许BUY、非空entry_conditions全部成立、无该标的pending、cash-reserved_cash大于min_cash_reserve；特征缺失或非有限值匹配为false。
- SELL须有持仓、available_quantity>0、计划允许SELL、非空exit_conditions至少一条成立、无pending。
- HOLD仅在实际有持仓且计划允许HOLD时留下；WAIT始终可用。因此有合法HOLD时即使无买卖也可能调用JEV，不能把“无买卖”一概等同这个原因。
- 所以空仓时常见是入场条件未满足，也可能是计划未允许BUY、现金约束等；仅凭该总原因无法确定哪一条条件失败。上游大多数挂单/最小手/风险拒绝已提前返回其他字符串，不会到这里。`Condition`支持gt/gte/lt/lte/eq，复核时须对照当时特征值、阈值、单位及plan版本，不能拿最新值解释历史WAIT。

相关原因须分开：

| 原因 / 阶段 | JEV关系 |
|---|---|
| `global model evaluation cooldown`、`shared model budget exhausted`、`strategy refresh cooldown`、`strategy model failure backoff` | 到达decider前拒绝，跳过JEV；各自门禁不同。 |
| `missing fresh raw minute facts`、`missing minute provenance`、`future/unavailable minute fact`、`account changed during strategy generation`、`strategy invalidation condition met` | fast_state构建失败，跳过JEV；更早pipeline还可返回NotFresh/WAIT_DATA_QUALITY。 |
| `expired plan or context` | decider调用JEV前退出。 |
| `no actionable strategy conditions` | 当前动作集合仅WAIT，跳过JEV；本轮可能先发生过flash刷新，不能据此断言全部模型零调用。 |
| `uncertain JEV evidence or plan`、`entry evidence insufficient` | 已获得JEV答案后阈值不满足，并请求刷新，不属于“未调用”。 |
| `expired during JEV request`、`JEV provider or answer validation failed` | 分别为请求期间过期、provider/校验失败；后者不单凭reason断言已发HTTP，需查准入/attempts。 |
| `WAIT_MODEL_PENDING` / `model worker pending` | 本轮无可消费异步结果；单凭它不能断言未调用或已调用JEV。 |
