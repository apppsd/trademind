## 实施记录（2026-10-19，Claude Code）

**方案**：保留datetime瞬间语义、零迁移。`memories_visible`的SQL只做粗预筛——TEXT上限加宽为`(as_of+2天).isoformat()`；ISO偏移差最大约26小时，故"真实可见（瞬间≤as_of）"的行TEXT必不越过该上限，预筛不排除任何真实可见行。精确判定在Python对每行`datetime.fromisoformat`后按带时区瞬间比较（`available_at > as_of`排除、`valid_until < as_of`排除、等时点可见），与`MemoryRecord.visible_at`逐条同语义；结果按解析瞬间排序（原ORDER BY TEXT跨偏移无意义）。存量混合偏移行无需迁移即被正确查询；naive as_of按domain require_tz契约显式拒绝。另清除原`vu > as_of and vu < as_of`永假死代码（行为不变）。`save_memory`存储格式未动（`ORDER BY`移除是该查询内部变化；dumps payload与TEXT保持原偏移）。

**回归**（`tests/test_memory_visibility.py`，7项，全部内存临时库、零网络/凭据）：Issue18-01两行反例（未来UTC记录在+08 as_of不返回、过去+08记录在UTC as_of返回）；visible与visible_at在UTC/+08/−05三偏移逐条一致（含等时点与+1微秒）；跨日与+14:00"TEXT日期越日"行（TEXT大于as_of但真实可见，旧实现必遗漏）；混合偏移存量行按瞬间而非TEXT排序；撤销/valid_until（边界==as_of可见）/全局与逐标的过滤保持；naive as_of拒绝。命令：`.venv\Scripts\python.exe -m pytest tests/test_memory_visibility.py tests/test_storage.py tests/test_context.py -q`（35 passed）。
