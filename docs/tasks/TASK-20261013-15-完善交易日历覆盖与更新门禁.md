## 2026-10-14 修复实施（原Owner回应独立复核）

针对复核三项缺口的实施与验证，改动仅`src/trademind/market/calendar.py`与`src/trademind/market/calendar_update.py`（冻结范围内），不改auto_paper/runner门禁行为。

- **有效覆盖区间与替换/校正**：官方输入按"其自身区间的完整权威陈述"处理。合并时先按现有日历的已确认段（`TradingCalendar._segments`）找出与`[incoming首, incoming尾]`重叠的段，整段撤回（段内旧日期不再保留，除非官方集合重新列出），区间外段作为历史原样保留；纯后延的官方文件仍是扩展。复核反例（旧2026-10-12/13/14 + 官方仅列12/14）现得：13不再是交易日（不再True）、`replaced_days=3`（test_merge_withdraws_wrong_dates_inside_official_span）。
- **已确认区间与未知空档**：`TradingCalendar`显式建模已确认段；相邻段间隙>14天（`MAX_CONFIRMED_GAP_DAYS`，取自最长确认休市≈12日历日+余量；默认fixture最大间隙10天不误分）记为**未确认空档**，不是休市：`covers()`=落在任一已确认段内，段外一律`CalendarCoverageError`；prev/next/add_trading_days拒绝跨越空档（`_require_no_hole_between`）；`coverage()`输出confirmed_segments与unconfirmed_gaps；`coverage_warnings()`逐空档提示"unconfirmed gap … obtain official data"。复核反例（2026+2030两段）现得`covers(2028-06-01)=False`、导航显式拒绝（test_unprovided_year_is_unknown_never_confirmed_closure、test_merge_cross_year_gap_leaves_hole）。
- **元数据一致性**：`.meta.json`新增`csv_sha256`、`replaced_range/replaced_days/carried_history_days`；`load()`读入字节并比对sha256，不一致置`meta_csv_mismatch`并在coverage_warnings提示"sidecar is stale"。CSV/meta经临时文件写bytes（修复Windows text模式CRLF使hash永不匹配的真实缺陷——该缺陷由本轮新测试暴露）后replace；meta写失败非完全原子，但半应用状态可被load()检出并可再次官方合并恢复（test_calendar_meta_hash_mismatch_detected、test_merge_meta_write_failure_leaves_detectable_state）。
